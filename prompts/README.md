# 提示词与契约

`writing.system.txt` 为论文正文任务的基础提示词。程序运行时读取它，补充当前操作、受保护块规则和输出要求。每次调用将实际系统提示保存为受管理对象，并在调用清单记录哈希与提示词版本。

`section-response.schema.json` 为响应契约说明；后端实际使用 `app/schemas.py` 的 Pydantic 模型验证字段类型，再执行来源、文献、事实、锁定和版本等业务校验。

`polish.system.txt` 专用于独立学术润写；`app/polishing.py` 定义润写规范、逐段响应契约与原文保留检查。它只加载明确适用于 `polish` 的项目条款，不使用定向修改的提示词与规则映射。

修改提示词后，先运行协议与候选稿测试，再使用真实模型的小样本验证。提示词变化不会改变旧调用清单。

`academic-expression.v1.txt` 是普通/整篇写作、agent 起草与修订、独立润写共享的表达规范；由 `app/writing_expression.py` 读取并加入实际系统提示。`academic-expression-review.v1.txt` 用于既有语义核验与 agent 衔接审查，要求按原文定位问题，不按句式词频评分。段落计划标记 `advisory=true` 时是程序建议，内容覆盖、依据和用户明确结构要求仍生效。来源筛选及验证口径见 `docs/写作表达优化_2026-11-06.md`。

多段候选另由 `writing_flow._discourse` 读取完整候选及提供的只读上下文，审查位置必须通过原句校验，再进入既有修订与回归流程。运行费用、覆盖限制和续写任务分配见 `docs/新版提示词程序落地_2026-11-06.md`。

后续规则与项目理解流程见 `docs/规则使用与毕业项目理解修复_2026-11-06.md`：绑定项目的起草先形成有来源编号的理解记录并按需补读；规则原句保留于 `rules`，条件与局部范围位于 `rule_applications`；写后每批最多12条核对适用条款。该流程包含额外模型调用，使用现有费用、权限和缓存保护。

第三至第六章通过 `chapter_materials` 提供实际表字段、页面组件、调用点、路由和测试定义；`visual_plans` 同时规定图表的真实结构、原始证据和段落解释任务。段落返回 `project_material_ids`、`visual_plan_ids` 与 `evidence_ids`，程序生成图表及交叉引用。具体职责、检查与真实项目预览见 `docs/第三至六章项目图表驱动写作_2026-11-06.md`。
