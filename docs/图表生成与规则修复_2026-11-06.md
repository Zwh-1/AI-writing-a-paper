# 图表生成与规则修复（2026-11-06）

本记录更新同日早先的“第三至六章项目图表驱动写作”方案。旧测试通过不能证明图表适合论文；本轮重新检查了实际预览和生成规则。

## 问题与修复

| 实际问题 | 本轮修复 |
| --- | --- |
| 三、四、五章重复页面—组件—函数清单，需求分析变成源码目录 | 按章节区分候选：需求入口及界面文案、数据设计及界面组成、具体功能调用及核心接口、测试设计与执行状态；相同静态映射不跨章复制 |
| 图题与正文出现大量“已读”“未解析”和源码路径 | 新增统一提示词 `prompts/academic-visuals.v1.txt`，标题面向读者，来源及阅读范围留在证据记录，影响结论的限制仍保留 |
| 数据表直接复制schema，默认值与说明丢失，联合约束不清 | 选关键标识、关系和业务字段；保留默认值、SQL COMMENT、自增和联合约束，复合键按组说明；有冲突或未完整解析的定义不自动制表 |
| 唯一外键被画成父子必然一一对应 | 唯一性仅限制上限：父端可以没有子记录；子记录是否必须引用父记录由NOT NULL/PK判断；引用非唯一目标不认定唯一父记录 |
| 关系图未展示外键目标字段 | 关系标注同时显示引用列与目标列，不凭 `_id` 名称猜连线 |
| 英文函数/路径从单词中间断开，ER实体高度不同导致大空白 | 英文按单词、驼峰和标点边界折行；ER实体自适应宽度、同行垂直居中，关系走连续通道 |
| 页面只有英文路径或模块名，缺少实际中文业务名称 | 读取界面标题与操作片段，按字面 `useTranslations` 命名空间读取对应中文JSON；登记组件、语言文件和路径配置的实际证据；预算不足不猜名称 |
| 每一类材料都被要求配图，出现凑图 | 图表计划改为按问题选用；具体文字分析也能使用项目材料。明确要求ER等图种时单独检查，不用无关表格代替 |
| 测试表把skip/todo混为普通定义 | 分别保留跳过、待实现、only和未提供执行记录；不自动生成通过率或成功结论 |
| 结构JSON合法但渲染失败，前几张图已写库 | 全批渲染预检后再保存；资源登记按事务回滚，失败不修改传入正文 |
| 同任务修订图表出现请求ID冲突，重复提案重复插图 | 请求标识绑定具体内容及位置；同批重复提案复用资源、追加交叉引用 |
| 表格没有说明关联检查，复用图表插在解释段之后 | 图与表统一关联独立说明段落；首次插入放在说明之前，同段可引用已有图表；表格也核对说明缺失、位置和占位内容 |

## 生成规则入口

先完善统一提示词，再接入章节写作、写作代理、篇章复核和单独图表生成。小容量请求使用同版本的摘要，避免重复堆入无关章节规则导致原文容量不足。已发布规则的范围和强度仍按项目配置执行；本轮没有改写用户已发布的241条规则记录。

规则参考 `D:/桌面/xiezuo/写作流程/md-thesis-writing/references/图表与drawio流程.md` 中“图表服务论证、关键字段、联合约束、图文互补、来源追溯、渲染不等于语义通过”的要求。这些附文作为资料使用，没有将文档中的工具或工作流指令提升为本任务授权。
