# AI 规则整理 403 修复与实测

日期：2026-10-22。

## 功能用途

“从课件整理候选”按本地关键词抽取规则，不调用模型。“AI 结构化整理规则候选”按批次发送允许外发的来源片段，提取强制要求、建议、正例和反例，检查每条依据能否在原文中定位，保存为待人工确认的候选。“片段上限”控制来源片段数量，不等同于页数；“从第几个片段开始”用于分批续接。候选确认和发布后才作为论文规则使用。

## 已修复

- 普通模型生成补上已有的 Cloudflare 拦截检查，与模型查询、余额查询及流式生成保持一致。
- 对 HTTP 403 的 Cloudflare HTML 返回明确的网络检查建议，不再把网页源码展示为业务错误；缺少正确 Content-Type 时也能识别标准 HTML 文档。
- 旧任务的列表和详情读取时转换历史拦截提示，保留数据库中的原始任务历史。
- Cloudflare 的 JSON 权限错误仍按接口错误处理，避免把所有经 Cloudflare 转发的 403 都认作网页防护。
- 403 不自动重试，不占用失败请求的项目预算预留，不生成规则候选。

## 本机实测结果与尚存问题

最初本机系统代理关闭，自由猫未运行，直接访问当前中转站的模型列表返回 HTTP 403 HTML。启动自由猫并由用户连接、开启系统代理后，模型列表查询成功，返回 10 个模型，包含当前配置的 gemini-4-argon；余额接口也成功返回有效 JSON。

原失败任务共选择 36 个片段。恢复网络后的首次重试收到 HTTP 503，任务正确记为 outcome_unknown，没有自动重发。随后用同一中转站列出的 gemini-2.5-flash 做一次独立的极短生成验证，也收到 HTTP 503。测试后已恢复原模型 gemini-4-argon。两次请求均保留远端结果待核实记录；不能凭未返回用量认定服务商没有计费。

另一次不含模型、消息的空请求收到 API JSON HTTP 400（model is required），进一步确认目前请求能够到达 API。模型列表、余额及参数校验可用，不能证明模型生成服务可用。当前生成仍受中转站 HTTP 503 阻塞，需要服务方恢复可用渠道或用户提供其他可用接口。

本次未修改已保存的 API 密钥，未将任何候选自动确认为正式规则，现有 438 条候选没有减少。刷新后的规则页面已通过浏览器检查：历史拦截提示可读、不显示 HTML 源码、无页面脚本异常。
