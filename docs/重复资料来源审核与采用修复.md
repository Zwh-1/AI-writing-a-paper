## 一、来源

- 分别保留每条记录的原文、文件、页码、图像、适用语境和底层知识单元。文字一致、图片字节相同、同属一张图，都不能单独证明两条资料含义相同。
- 复核原文件实际SHA256、文件启用状态、解析状态、原页是否排除、当前解析版本和完整来源范围。缺原件、局部校对摘录、未完成的底层转录、失效来源均阻止采用。
- 原句必须能在自己的主来源中对应；只允许整条来源的等价排版规范化，不允许先把不同候选改成同一段摘录再归并。
- 标题、目录等短文字加入原页位置；参考资料加入原页图像语境。评分等级、来源角色、来源政策和正反例用途分别比较。
- 区分“提取记录数”和“不同来源位置数”。同一页、同一评分表行重复抽取的两条记录，不会被虚报成两份独立来源；不同页的重复出现位置继续保留。
- 多层归并会展开全部历史来源。例如B并入A、A再并入C，C仍能追溯B。被后续修改的历史记录也不会悄悄退出来源链，而是标记改动并阻止下一次采用。

## 二、审核

新增独立的本地程序复核步骤。复核只保存来源清单、逐项检查、条款快照和版本指纹，不改变条款状态。

复核包含原句内容、数值、单位、否定、适用范围、执行条件、用途、评分等级、完整语境，以及每条记录既有审核依据是否完成、是否仍匹配当前来源。缺少审核指纹、审核状态未完成或置信度不足时阻止采用，不降低已有阈值。

本轮发现旧26组“可归并”结果中，有6组、12条记录的既有审核实际上仍为`needs_full_source / completed=false`。这些记录已从直接可归并集合排除，不能利用旧的用途分类绕过完整来源核验。

界面明确显示“程序复核”，保存`review_kind=local_structural_review`及`human_approval=false`。程序检查通过不代表人工逐字核验，更不代表全部图片文字识别完成。

## 三、采用

界面按“1. 来源 → 2. 审核 → 3. 采用”显示。复核通过后，预览保留记录的状态与用途、归并条数、保留的原始记录数及来源位置数。未复核或未通过时，采用按钮不可用。

采用时服务端再次校验复核指纹。原件、来源原文、定位、解析版本、条款、条件、既有审核、来源政策或历史来源发生变化，都必须重新复核。旧归并接口也执行同样的完整复核，不能绕过界面限制。

采用只将额外提取记录标为归并／排除，保留主记录原状态、原用途和原条件。本轮12组的主记录全部保持“仅供参考”，没有新增生效规范，也没有修改140条生效建议或规则包V33。

每次采用保存完整来源清单、审核凭据、采用前后原始行及恢复入口。恢复后旧审核凭据撤回，再次采用必须重新复核。若归并后的成员已被修改，恢复操作拒绝覆盖后续修改。
