# 0.6.0 证据知识库实现与验收

日期：2026-10-26。

本版保留原有RAG和文献库，新增独立管理的证据知识库。入口为“文献与术语 → 证据知识库”。核心流程是先定位，再读取原文及上下文，然后针对具体论断核对；分段和模型解释都不自动成为事实。

## 已实现范围

| 需求 | 实现 |
| --- | --- |
| 原件、结构与索引分离 | 继续使用不可变原件；新增解析版本、原文单元、索引子窗口及向量表，不改写旧来源编号 |
| 结构化原文与位置 | PDF保留物理页码、文字位置与可定位的边界框；DOCX保留原生标题路径、段落和完整表格，不伪造物理页码；OCR和人工转录与原生文字分别登记 |
| 多种分段方案 | 支持段落候选、整页上下文、旧版提取和人工修订版本；能够并排比较、读取历史原文及切换版本 |
| 调整证据边界 | 读取前后单元或明确字符范围；将实际读取范围另存为带原文位置关系的新版本，旧版本继续保留 |
| 不确定性与争议 | 记录边界、OCR、阅读顺序、表格关系、含义解释等争议；解决争议后仍需另行确认原文，不能自动变为已核对 |
| 原文审核与论断核验 | 原文确认要求核对人、说明、原件对照及问题确认；论断支持性单独绑定逐字引句、条件、原文版本与核对人 |
| 独立证据检索 | 原始文献和结构单元均可检索；可限定“已核对且无争议”，支持按原件、状态和文字筛选、分页 |
| 本地混合检索 | 子窗口只用于索引；支持全文、已安装本地向量、RRF和独立Cross-Encoder；重排使用定位窗口，返回的证据原文保持完整，模型不可用时明确回退 |
| 普通写作 | 同时读取来源与完整知识单元，记录实际读取范围、版本和缺口；知识单元可关联书目和正文段落，未读取的编号会被拒绝 |
| 有据写作 | 章节初始化、检索和读取工具接入统一知识服务；原文阅读后生成独立文献证据，保留条件、争议、范围和权限版本 |
| 上下文预算 | 超出范围返回分步读取提示和缺口，不返回截断原文并声称已完整阅读；片段预览不生成证据 |
| 缓存与过期传播 | 原文、分段版本、用途、权限或页面适用性变化后，旧观察和关联候选不能作为当前依据继续采用；章节选择变化单独失效，不撤销其他章节的原文证据 |
| 普通文件批量入库 | 多选原件、预览、编辑题名/作者/年份后提交；按原件哈希复用，保留已有人工书目，重复提交同一预览不重复导入 |
| 进度与恢复 | 解析及知识库任务进入任务中心；文件失败单独列出并可重试，已完成解析和向量批次保留；自动索引不覆盖当前人工选择的版本 |
| 引用追溯 | 显示当前正文论断、书目及原文单元；支持独立AI辅助检查和逐条人工引用核对，模型判断与人工判断分开记录 |
| 检索与语义评测 | 生成最多20条明确标为未核验的定位草稿；支持编辑实际问题和标准单元，对照旧检索与新检索；语义判断另行逐条提交，不由召回率代替 |
| 导出与备份 | 正文导出附原文单元、引用范围和核对记录的冻结JSON；完整本地数据库备份覆盖新表；旧版不完整云同步会阻止含新知识库的传输 |

文献依据仍不能直接证明本项目的测试执行、部署或实际效果。待核对原文可以用于形成待审候选；未处理争议、缺失上下文和不支持的论断不能被模型一次自评自动提升为已验证。

## 使用流程

1. 打开“文献与术语”，在“证据知识库”选择“批量导入原件”，或使用已在项目内的研究文献。
2. 选择段落候选或整页方案，点击“构建结构化版本”。任务在本机运行，使用已安装模型，不自动下载或调用付费模型。
3. 检索后点击“读取与核对原文”。并排查看原页、转录和上下文；阅读顺序、表格或边界有疑问时登记争议，并扩大阅读范围。
4. 填写核对人和说明。确认原文前逐项处理提示的问题；调整文字或边界时另存新版本。可在版本列表中比较或恢复其他版本。
5. 在“具体论断的支持性核对”输入论断、逐字原文引句和适用条件。原文已核对并不表示任意论断获得支持。
6. 在“为章节选择证据”选择所需单元并保存。普通写作和有据写作都会保留实际读取的单元、上下文与版本。
7. 在“正文引用与原文对应”查看论断和具体来源，按需执行模型辅助检查或人工核对。AI检查使用项目已有模型和费用预算；它不会自动成为人工确认。
8. 使用“对照评测”保存问题和标准原文，观察定位指标，再逐条记录人工语义判断。

## 数据升级与回退

程序版本为0.6.0，数据库版本从7升级到8。迁移通过校验日志按事务执行；升级前保留 `migration-before-writing-v8.sqlite3`。旧程序会拒绝较新数据库。不要直接用旧数据库备份覆盖升级后新增的正文。

现有 `files`、`sources`、`bibliography` 与历史引用继续使用原编号。新版本切换和人工修订只新增或切换知识单元层，必要时提示下游复查；原文是否已核对、具体论断是否获得支持分别记录。

初始化脚本 `scripts/initialize_evidence_knowledge.py` 会先保存完整数据库副本，再增量建立结构单元及本地索引。可用 `scripts/validate_evidence_knowledge.py --output <新目录>` 在数据库副本上只读核对真实原件；默认只比较全文定位，可加 `--vectors` 使用已安装本地模型，始终不自动下载或调用付费API。

## 验证记录与边界

完成过一次900项后端全量回归，全部通过；最后一轮143项重点复验也全部通过，覆盖知识单元工具、支持性限制、导出、缓存、旧片段绕过排除的阻止，以及避免重复检索和重复重排。已完成前端TypeScript与生产构建。测试记录位于本机 `.runtime/evidence-knowledge-regression-final.xml`、`.runtime/knowledge-release-final-v2.xml` 等文件。测试客户端有一条依赖弃用提示，前端存在原有包体积提示。

真实资料验证在独立数据库副本运行：30篇有效研究文献全部解析成功，建立1310个原文单元，耗时约50.2秒；原件登记、来源、书目、正文及引用的前后指纹一致。副本报告位于 `.runtime/evidence-knowledge-real-audit-20261026-v2/report.json`，不进入源码仓库。

副本还使用20条自动生成的定位草稿对比了两种全文检索：旧版原页Recall@10为0.95、MRR为0.858；结构单元原页Recall@10为1.00、MRR为0.813。该组草稿来自原文，不是真实用户问题或人工语义标准；不能据此宣称新方案语义准确率提高，MRR也没有在这组定位对照中提升。此轮副本对照未启用新增向量。

浏览器验证覆盖原页加载、上下文与条件保留、争议处理、原文审核与论断支持性分离、当前正文引用核对、边界修订和版本恢复、导入预览、评测与390px布局。合成资料的人工记录只用于检查操作流程，不混入实际文献库。结果和截图保存在 `.runtime/evidence-knowledge-browser/`。

## 实际库启用结果

实际数据库已完成初始化并保留独立备份 `data/backups/before-evidence-knowledge-20261026-143838.sqlite3`。30篇文献对应1310个原文单元、12667个定位窗口，已全部建立本地向量。初始化前后原件登记、来源、书目、正文和引用记录的指纹一致。原文单元目前均为待核对，没有自动代填人工确认。

本地程序已重启到0.6.0。实际检索返回5个结果，完整原文读取成功；原始召回阶段跳过重复重排，合并后只执行一次40候选Cross-Encoder重排。相同问题两次本机实测约24.4秒与20.1秒，没有新增付费模型生成记录。CPU完整重排仍有等待时间，这两次耗时不代表所有问题的性能保证。记录见 `.runtime/evidence-knowledge-live-smoke.json`；初始化结果见 `.runtime/evidence-knowledge-live-init.json`。

真实文献的逐条语义核对、复杂表格和阅读顺序的准确性仍需对照原页验证。系统提供问题队列、版本和修订路径，不宣称存在对所有文献都正确的唯一分段方式。Docling、RAGFlow属于备选方案，本版使用内置本地结构解析和现有检索组件。
