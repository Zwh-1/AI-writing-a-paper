# 0.2.1：设置页密钥显示与保存修复

日期：2026-10-21。

## 问题原因

1. 检测模型会先保存设置，再清空密码输入框；旧版没有立即采用后端返回的保存状态，所以徽标可能仍显示“待填写密钥”。这会让已保存的密钥看起来消失。
2. 折叠预算设置的预留费用字段为 `min=0.01`、`step=0.1`，默认值为 `2`。该值不符合从0.01开始的步进，浏览器在提交事件触发前拦截，隐藏字段又不容易显示校验提示，因此保存看起来没有反应。

## 已修改行为

- 保存与检测共用明确的持久化流程，立即采用后端返回的密钥状态和标准化配置。
- 完整key不回填；成功后显示“已保存”、脱敏尾号和“留空继续使用”，无需重复输入。
- 检测模型失败时区分“保存已成功”和“检测失败”，不会让用户误以为密钥被删除。
- 预留费用和单价支持合法小数；提交改由后端验证并将错误显示在表单内，不再被折叠字段静默阻断。
- 保存、检测和删除有处理中状态，期间禁用重复提交。
- 保存失败保留用户刚输入的密钥，显示具体原因；未通过保存不会错误标为已保存。
- Windows密钥先加密并回读校验，再通过同目录临时加密文件原子替换；加密或写入失败时保留旧文件。
- 密钥保存失败时不提交新的接口配置。
- 较矮窗口中的侧栏可滚动，设置入口不会被挤出可点击区域。

## 验证

- 新增7项后端密钥保存与回滚测试。
- 13项设置页浏览器回归：首次检测、重新输入后保存、刷新保留、空输入保留旧密钥、小数参数、折叠字段错误、检测失败、保存失败、处理中防重复、显式删除等。
- 所有测试使用独立数据目录中的假密钥；模型列表响应被拦截模拟，没有使用用户真实密钥或发起收费生成。
- 当前用户的加密密钥文件在升级前后保持一致，仅核对加密文件是否变化，不输出其内容。

具体结果见 `settings-regression-report.json`、`backend-tests-v0.2.1.xml` 和 `v0.2.1-validation.json`。

## 使用

重新通过启动快捷方式打开新版工作台，进入“接口与设置”。如果显示“已保存密钥”和脱敏尾号，可直接继续使用，无需重复填写。只有更换密钥时才输入新值并保存。
