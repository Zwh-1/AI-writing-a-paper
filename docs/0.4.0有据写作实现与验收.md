# 0.4.0 有据写作：实现、使用与验收

日期：2026-10-23。方案来源为论文目录的V4.0详细实施方案。新增入口是左侧“有据写作”，普通写作、资料、规则和历史版本继续保留。

**完成状态补充：尚未全部完成。** 2026-10-23独立核查发现旧采用入口没有适配统一服务，变化传播仍为项目级保守失效，修订缺少旧/新关键命题独立回归，衔接扩展及分项诊断也未完整落地。102个真实样本的人工评分为0，真实项目尚无人工核验及严格交付闭环。下文操作说明适用于已经实现的新流程，不能理解为全部25项任务或真实论文已经验收。详见[完成情况核查报告](D:/桌面/论文/论文写作工作台_完成情况核查报告_V4.0_2026-10-23.md)。

## 已实现的操作流程

1. **论文与任务**：发布研究问题、研究范围、方法及结论边界；给已有章节登记写作任务和具体证据；建立阶段模型配置。
2. **代码与证据**：绑定本机项目，选择外发策略，冻结来源；检查纳入/排除/失败清单；从精确代码范围登记证据。
3. **写作与核验**：按“调查 → 事实与结论判定 → 判定复核 → 正文 → 逐句关联 → 含义核对 → 衔接检查”生成候选。原正文只在采用后更新。
4. **模型诊断**：16类34变体、可重复采样，真实调用和人工判定分别记录。正确答案和失败标准不进入写作者输入。
5. **全文与交付**：逐章读取连续原文，按索引定位跨章需要对照的原始段落。不能可靠覆盖的范围继续列为未决项，可登记当前全部版本的人工通读。

来源默认为仅本机；只有明确允许的选定内容及其派生依据才可外发。代码中的说明不能赋予执行Shell、读取其他目录或部署的权限。

## 数据与版本

新增三批迁移，数据库版本为6。启动时验证迁移校验和，迁移使用事务并保存一致性备份。高版本库不会被旧程序静默重置。

源码使用内容哈希冻结，保留读取窗口、覆盖、规则和解析状态。TS/TSX用随包TypeScript语法解析器建立线索；动态调用保留未知。Solidity和Circom目前主要提供精确范围与静态符号线索，不声称完整语义或运行时调用图。

有效UTF-8原文中已经存在的U+FFFD字符会原样保存并显示质量警告；不把它误作本次解码失败，也不猜测丢失的文字。真正无法解码的字节仍列为覆盖缺口。

正文仍采用原有Tiptap结构。句子分析独立保存，使用Unicode码点和前端UTF-16转换；点击“定位第n句”可以在正文编辑器选择对应文本。编辑后旧映射不能自动当作当前映射。

## 输出与核验

- 一句可以关联多个独立论断。来源编号存在不等于来源支持论断。
- 研究目的和章节任务以作者说明形式关联，不自动变为实现或运行结果。
- 测试定义、源码观察、实际执行记录和部署记录分别管理。
- 逐句分析分小批次，避免一次标注过多句子耗尽输出；正文和证据不因批次变化被改写。
- 模型辅助支持、人工判断、证据有效性和正文采用分别记录。生成结束不自动获得人工确认或配置资格。
- 文献引用只接受本次有原文证据的已有书目ID，仍由原排版机制处理编号。

普通草稿采用可以保留未决项。严格采用需要当前版本、完整映射和明确人工核对，且无法绕过越权、缺来源、锁定、结构错误和基础版本冲突。

## 恢复、费用与采用

每个阶段独立排队。已完成响应可从本地检查点重新解析；已发送但远端状态未知时不自动重发。租约代次阻止旧执行者覆盖新任务。

新写作服务的整体采用、部分合并以及联合补丁使用事务、基础版本和幂等标识；旧写作`/accept`入口尚未统一到该服务。部分候选先形成合并稿重新核验，不能继承未采用的前提。跨章严格补丁涉及彼此修改的前提时会返回联合复核要求，目前对应完整联合候选复核路径尚待补齐。模型配置更新保留旧步骤、响应与费用；远端未知不能通过换配置绕过。

费用沿用现有账本。可选账单核对只在币种、模型、请求数量和报告token与一个确定区间匹配时结算；缓存token口径有独立记录。只能得到组账单时保留组总额，不人为分摊逐笔费用。不能匹配的预留继续保留。

## 实际验证及其边界

可重复的自动化结果见本目录`writing-agent/backend-tests.xml`和`browser-report.json`。浏览器使用明确标注的合成fixture，测试人工按钮只验证交互和事务，不冒充真实模型人工质量验收。

已执行的真实模型校准：102个样本，由16类34变体重复3次组成；多阶段和多轮题产生额外HTTP调用。完整回答和阶段记录保存在`real-model-acceptance.json`。人工语义评分未被伪造为通过。

实际Edu SBT试点包括：

- SBT转移条件、继承声明与测试定义：七个阶段完成，保留模型指出的具体问题及审阅状态。
- 后端暂停动作与前端执行/Hook的跨模块关系：原始失败及修复后最终结果分别记录于`extended-real-project-pilots*.json`和`cross-module-pilot-final.json`。
- 本地运行记录写作：在隔离副本编译67个Solidity文件，运行一个既有转移限制用例通过；将它作为实际运行记录再生成小节，按待核验草稿采用。该结果不代表公网部署、生产状态或完整测试套件通过。

实际测试过程中发现并修正了片段读取与截断含义混淆、可选未知结果阻断静态写作、重复输入导致预算超限、句内标注结构差异、单次标注输出过长等问题。失败候选和费用记录保留，不删除后宣称全部首轮成功。

真实校准也发现模型会超出指定篇幅、把评估任务的元描述写入正文，或过度否定合理的限制性说明。因此本版不授予“全部论文自动正确”的标记。正式论文的研究范围和最终结论仍需用户审阅。

## 交付与兼容

排版页提供草稿/严格交付策略。导出附加源码版本、句子—论断—证据映射、覆盖及未决项。

本地备份包含新表和冻结资源，排除密钥，并清除需重新绑定的本机仓库路径；恢复到隔离目录。恢复后的来源默认为仅本机。

旧云同步格式不能完整携带新增分析，含新写作对象的项目会明确返回不支持，需使用完整本地备份恢复。没有静默降级为不完整的同步包。

## 运行

继续使用现有启动快捷方式或PowerShell7.6.5 Core的启动脚本。正式数据和验收数据分别保存，实际试点没有覆盖用户的正式研究简报或正文。

便携包包含Node与TypeScript索引运行组件，不包含项目数据、真实模型验收输出、源码快照或API凭据。发布机器上的人工质量记录不自动转移为另一模型配置的资格。

现有测试依赖仍会报告Starlette关于httpx测试客户端的弃用提示；这是既有依赖警告，未通过关闭警告来隐藏。
