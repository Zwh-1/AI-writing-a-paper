# 论文图表功能修复

本次针对新增图表功能检查了生成布局、编辑状态、预览与导出一致性、正文插入以及 AI 来源链路。

## 已修复的问题

| 问题 | 修复后的行为 |
| --- | --- |
| 多条 ER 关系连接到同一个位置，容易混淆 | 关系分别选择接入点，路由对重叠路径增加避让；基数标签单独测量 |
| 长关系标签合法但无法生成 | 按实际字体宽度测量，自动换行并为标签增加间距 |
| 回路布局依赖节点输入顺序 | 识别返回边后排布前向流程，回路从外围返回 |
| 不支持流程自循环和实体自关联 | 两类关系均可使用同一 source 与 target，分别连接不同端口 |
| UML 关联类型不明确 | association 只连接参与者与用例；include 和 extend 连接用例 |
| 完全重复的连线和字段名被静默接受 | 保存或预览前明确报出重复项 |
| 切换类型、关闭或刷新丢失未保存内容 | 按项目、章节和类型分别恢复草稿，包括待编辑的 AI 候选 |
| 三线表增减列依赖手改代码 | 增加直接增删列、结构撤销和多行单元格 |
| 无效表格 JSON 可能破坏编辑表单 | 表单先检查可编辑结构；无效内容留在代码编辑区并显示验证错误 |
| 重新预览仍下载旧图片 | 比较实际渲染哈希；重新生成的结果保存为新产物后再提供新下载 |
| 保存响应不明后重试可能重复创建产物 | 同一保存请求幂等处理；内容不同不能复用请求编号 |
| 正文保存冲突后重试可能重复插图 | 已插入的同一结构节点只重试保存 |
| 在表格单元格内操作会把图片插进表格 | 图片和新表格插入到外层表格之后 |
| 连续修改未保存候选丢失来源记录 | AI 修改继续加载并检查完整的来源版本链 |
| Word 表格换行和高行分页不完整 | 保留硬换行与多段内容，允许过高的数据行跨页 |

历史产物保留原始文件。重新生成、预览并保存后创建新版本，已采用的正文不会在后台被自动替换。

## 验证范围

后端回归覆盖正文、导出、写作、润写、来源权限和图表功能。专项浏览器检查覆盖草稿恢复、行列编辑、无效 JSON、源代码导入、预览缩放、旧图重新生成、保存冲突重试和表格内插入。AI 流程使用隔离项目与模拟响应。

已执行 20 节点流程、4 个参与者与 12 个用例、9 个 ER 实体的边界场景。整篇 Word 样例通过本机 Word 实际渲染并逐页检查，桌面和 390 像素宽度界面均已检查。

本机验收输出位于 `.runtime/paper-visuals-repair` 与 `.runtime/paper-visuals-qa`，不进入公开源码。
