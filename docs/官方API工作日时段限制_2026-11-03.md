# 官方 API 手动授权与工作日时段限制

在“接口与设置”的 DeepSeek 接口区域保留工作日高峰时段限制，并新增默认关闭的官方 API 总开关。

- “允许使用 DeepSeek 官方 API”默认为关闭，全天禁止调用，必须由用户手动开启。关闭总开关后不会因午休、下班或周末自动恢复。
- 设置处持续提醒：当前 DeepSeek 官方 API 花费高，缓存命中率非常低，开启后可能产生较高费用。
- 开启总开关后，下面的工作日高峰时段限制仍然生效；“手动允许官方 API 在上述时段调用”是独立的第二个开关。
- 旧版本仅保存的高峰时段放行记录不会自动开启新的总开关。

- 时区固定为北京时间 `Asia/Shanghai`。
- 周一至周五的 `09:00–12:00`、`14:00–18:00` 默认禁止官方 API 调用；开始时刻包含在内，结束时刻不包含。
- 周末和其他时段不受高峰时段限制，但仍需先手动开启总开关。“工作日”按周一至周五判断，不额外解释节假日或调休。
- “手动允许官方 API 在上述时段调用”默认为关闭。用户勾选后保存为持久设置，取消勾选即恢复限制。
- 官方接口按实际请求主机名 `deepseek.com` 及其子域识别，不按模型名字或接口名称识别，中转接口不受误伤。
- 模型列表与余额等只读查询也遵循以上授权和时段限制；编辑或保存本地接口配置不需要开启。

限制同时作用于直接调用、任务指定接口、非流式和流式生成、智能体工具及自动接口池。自动切换会跳过受限官方接口，全部接口均受限时也不能退回旧配置绕过限制。

请求开始前先检查，实际发送 HTTP 前再次检查，避免校验期间跨入限制时段，或已创建连接后关闭手动放行开关。被拦截的调用会明确提示未发送，不自动重试，不把费用状态记为未知；发送前被拦截不占用预算。已经提交到远端的请求不追溯取消。

设置接口为 `GET/PUT /api/v1/deepseek/official-api-policy`，保存参数支持布尔值 `allow_official_api`、`allow_official_peak_hours`，至少提供一项，未提供的开关保留原值。运行状态包含两个开关、费用提醒、当前是否限制、时区与高峰结束时刻。只有总开关已开启且当前仅被高峰限制拦截时，才返回下次自动可用时刻；总开关关闭时无自动恢复时间。

关闭总开关时，拦截错误为 `OFFICIAL_API_DISABLED`；总开关已开启但高峰时段未单独放行时为 `OFFICIAL_API_PEAK_HOURS_BLOCKED`。两种错误都包含费用提醒，且不会自动重试或产生远端请求。

2026年11月3日验证：双层授权和发送边界相关测试102项通过，原接口池、接口配置、模型路由、传输配置及任务端点回归96项通过；前端TypeScript检查及生产构建通过。隔离浏览器验证了两开关独立保存、刷新后保持关闭、只开启高峰放行不能绕过总授权、禁用时允许本地编辑而禁止检测模型。验收使用独立数据和模拟接口，未调用真实官方API。

当前本机已有整篇写作任务运行。按用户明确选择，保留写作运行，暂不重载生产server及worker；新后台门禁需要在后续完整重启后生效。仅刷新网页或只替换前端构建不会更新已加载的后台代码。
