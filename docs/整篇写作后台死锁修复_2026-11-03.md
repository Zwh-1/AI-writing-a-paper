# 整篇写作后台死锁修复（2026-11-03）

实际后台在第一章“检索并准备文献原文”停滞。单独执行写作准备函数能在约25秒到达模型调用边界，但未覆盖后台进程的父进程监控线程，因此不能证明后台可用。

## 现场根因

使用只读进程采样抓取仍然存活的后台进程，确认主线程停在 NumPy `_multiarray_umath` 扩展加载，进入 OpenBLAS DLL 的 Windows CRT 锁等待。父进程监控线程正阻塞读取 `sys.stdin.buffer.read(1)`。watchdog 已写下超时记录，但其 `os._exit(3)` 又卡在 DLL 退出清理，监督进程仍在等待子进程退出。

隔离对照不访问论文数据和模型接口：无输入监控时 NumPy 约0.20秒导入；先启动阻塞式输入监控则超时；Windows `ReadFile` 仍可复现；改为等待父进程句柄后约0.26秒完成。

## 修复

- Windows 监控父进程句柄 `WaitForSingleObject`，不读取标准输入；队列子进程的标准输入改接空设备。
- 保留每个数据目录的监督锁与执行锁，避免替换过程重复执行任务。
- Windows 强制退出预绑定 `TerminateProcess`，避免在原生 DLL 已死锁时再次进入 CRT/DLL 清理；其他平台保留 `os._exit`。
- 写作打包为格式修复额外预留2048字节输入空间，避免首次请求刚好通过、追加格式校验说明却超限。
- 对已经返回但结构无效的首次草稿，恢复时逐字比对本任务保存的响应，只复用该响应进入既定格式修复；不重复生成首次草稿，也不把降级文字当作有效章节。其他未完成或结果不明的远端请求仍需原有确认。
- 原文权限、候选校验、费用预留和未知远端结果的恢复规则不变。

真实子进程测试覆盖数值库导入和运算、正常退出、父进程被终止后子进程退出、异常退出后重启、独占锁和 PowerShell 停止脚本。额外测试复现阻塞式输入监控与原生库加载冲突，确认强制退出可结束该进程。
