## S1–S6 的落地情况

1. **S1：返回值和导出契约。**业务记录不再被当作失败任务；导出历史不再为 TeX 记录生成不存在的 DOCX 链接。旧导出记录根据磁盘上真实存在的文件生成产物描述。
2. **S2：文献与当前解析。**原文献编辑和连接器操作共享同一变更服务；当前解析的全文/向量能力由既有知识服务承担。pages/sources 继续保留原件预览和历史身份，不覆写旧证据。
3. **S3：来源与提交。**来源关系有类型、版本和明确所有者；失效向随记、消息、派生内容和正文依赖传播。个人随记与模型输出保持未核实身份；统一提交不会授予严格核验状态。
4. **S4：原工作区消费。**文献页增加接入、发现、对照阅读、对话与随记；问题阅读内可展开共享阅读器；研究成果页接资产/画布；原交付页接多格式导出；原设置页接解析/执行/协作。
5. **S5：兼容迁移与依赖收敛。**旧接口和旧模块保留适配；新增接口采用既有 v2 注册表映射到领域路径。数据库增加关系与版本表，不重置旧记录身份；旧所属关系不能核实时标为 unknown。
6. **S6：协作与运维。**完整包恢复/分叉验证关系；只读查询投影打包进便携版和 Docker；研究记录支持基于共同原件基线的合并和冲突处理，提供配置/能力发现。

## 新的使用入口

- **文献与知识**：文献接入、文献发现、对照阅读、学术对话、思维随记。原问题阅读可展开相同阅读器。
- **阅读选区**：保存高亮/批注、建立候选证据；批注可转随记。来源卡片回到对应原文。
- **思维随记**：选择关联章节、保存，再作为未核实草稿追加到章节；来源关系与版本保留。
- **研究与成果**：共享资产库、自由画布和回编辑。生成图片可指定章节，通过持久待办进入正文。
- **写作工作台**：学术对话、评论、公式、画布、补全。待插入资产核对目标正文版本后保存并消费。
- **排版与交付**：Word、Markdown、TeX 工程使用统一检查和快照；历史展示实际文件。
- **接口与设置**：解析、执行、能力状态、缓存与研究记录协作。

### 研究记录协作的边界

`research-sync.v1` 合并研究记录，不传输整份原件、解析版本或正文。两端先通过完整知识包建立相同身份的项目基线，再导入研究记录；缺少来源基线时返回冲突提示，不补造原件。

- 消息以追加为主；同 ID 的不同消息进入冲突。
- 可编辑记录按基线哈希/版本快进；同时编辑保留两侧内容。
- 删除保留墓碑；本地历史与远端分支历史不丢弃。
- 冲突可保留本地、采用远端或另存远端；消息冲突不允许覆盖原消息。
- 相同数据包重复导入返回幂等回执。

原旧版项目同步协议对不支持的新知识对象仍保留明确阻止机制；本轮没有把这个协议冒充成全项目自动同步。新的记录合并入口和完整知识包分别承担增量记录协作与完整数据保全。

### 全量回归中的已有失败

在本轮中期执行全量1625项，结果为1606通过、19失败；报告保存在 `.runtime/architecture-full-regression.xml`。这些失败分为：

1. **4项润写拒绝场景**：任务已拒绝改变数字/单位/完成状态的结果，而旧测试辅助函数先断言任务必须 succeeded。使用本轮修改前保存的 tasks.py 在独立解释器中也复现同一失败。
2. **15项费用对账场景**：测试模拟 `/v1/usage`，工作区已有 provider/adapter 实现选择 `/v1/dashboard/billing/subscription`，模拟传输断言失败。它们集中在 test_summary_billing 与1条规则批次费用测试。本轮没有为了通过断言而覆盖用户原有接口适配改动。

首次全量还定位出本轮的跨项目资产状态码、书目核对状态兼容问题，随后已修复，并在最终重点回归中通过；另在后续重点回归中修复了图片兼容文件名和维护服务提取遗漏的 re 导入。

因此，这次交付的结论是“本轮架构与工作流验证通过”，不能描述为“整个仓库全部测试零失败”。
