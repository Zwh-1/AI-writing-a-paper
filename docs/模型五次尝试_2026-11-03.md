# 模型五次尝试

## 最新规则：DeepSeek 耗尽后自动接替 GPT

2026-11-03 补充修复：DeepSeek 与 GPT 现在各有独立的路线额度，每条路线默认最多5次；同一路线内的网络重试、端点轮换和格式修复仍共享额度，不能各自补满5次。下文早期“主备共同最多5次、不允许第6次GPT”的实现记录已被本节规则替代。

DeepSeek 连续5次明确安全失败（例如429限流或HTTP连接建立前失败）后，自动以同一任务、system、user、manifest、图片和阶段请求选项调用已启用且配置完成的 GPT，用户无需手动切换。显式保存较小的 DeepSeek 次数上限仍生效，耗尽后可以更早自动接替；401/402/403/404等明确拒绝仍可提前切换。GPT 使用自己的1至5次配置，耗尽后停止，不能再自动切回DeepSeek形成循环。默认最坏情况为5次DeepSeek加5次GPT，所有请求仍经过原预算和来源检查。

成功接替后当前任务的后续请求与恢复继续使用GPT，避免每一步都重新失败5次。路由保存在 `settings.model_routing_task:<task_id>`，不改全局模型。新任务从DeepSeek开始；改变任务指定接口或显式模型选择时旧自动路由不再匹配。DeepSeek成功、GPT成功以及新逻辑阶段都会正确重置其失败计数；阶段内已消耗的尝试机会不会因成功或嵌套进入而重新补满。端点池全局健康计数不用于决定某个任务是否切GPT。

部分输出、截断响应、读超时、5xx或远端结果未知的当前请求不会自动重发；否则不能保证不重复处理。只检查当前失败run的stream_chunks，前一章节或单元已经成功的流式片段不再阻挡后续独立请求回退。已完成阶段仍走原恢复缓存，不重复生成。官方API总授权/高峰限制、取消、原文权限、上下文容量及费用预算仍优先生效，不能通过回退绕过。

取消检查同时覆盖外层网络重试和端点池内部的每一次实际尝试。已知在下一次HTTP前取消且当前run没有流片段时，不会误记为结果未知或继续占用预算。规则任务的预算唤醒也读取任务已切换的实际GPT路由，未授权GPT或GPT子预算不足时保持budget_blocked，不反复错误排队。

普通写作中 `provider_profile=primary` 表示首选DeepSeek，允许自动接替；主模型图片能力验证仍严格只测主模型，避免把GPT能力登记成DeepSeek。智能体也接入相同路由，保持工具frame、Responses items和别名；能力及账单归到实际模型，跨账户不拿DeepSeek查询基线推断GPT扣款。

改动：`backend/app/provider.py`（独立route额度、保留安全失败资格、计数）；`model_routing.py`（自动切换、任务路由保持、作用域隔离）；`tasks.py`（当前run输出标识、每次重试取消检查）；`writing_agent/provider_adapter.py`（统一路由与实际模型归属）。前端三处说明同步更新。

验证入口：`tests/test_deepseek_gpt_failover.py`、`tests/test_agent_gpt_failover.py`，并回归现有路由、五次额度、格式修复、固定端点、官方授权、恢复缓存及智能体用例。最终报告位于 `.runtime/diagnostics/deepseek-gpt-automatic-failover-final.xml`。全部使用隔离数据和模拟HTTP，不发送真实收费请求。

完整16文件回归395项通过；随后新增的池内取消及规则预算边界验证单独记录在 `.runtime/deepseek-gpt-failover-tests.xml`、`.runtime/diagnostics/deepseek-gpt-failover-boundaries.xml` 与 `.runtime/gpt-failover-rule-budget-tests.xml`，文件间有重叠，不将数量简单累加。前端TypeScript与生产构建通过。

按用户此前明确选择，本轮不重启生产server/worker；源码及前端构建完成后，新后台行为需完整重启才能加载。

## 早期实施记录

模型默认最多有5次机会，包括第一次请求和最多4次自动重试。接口设置中的“最多尝试次数（含首次）”支持1至5，已配置接口已更新为5。明确保存为1时仍尊重该设置。

此次修复了资料总结、智能体、规则审核等阶段把次数无条件覆盖为1至3，以及智能体连接建立前错误没有标为可重试的问题。HTTP尚未发送的连接失败、明确限流等可恢复错误会使用剩余机会；任务进度会显示重试次数，尝试记录留在原任务中。

完整响应不符合结构化协议时，正文、论证单元、独立核验和智能体会尝试修复格式，最多5次。已经完成的单元不重复生成。原始响应和每次校验结果仍保存，不把格式错误或没有来源支持的内容标为通过。

同一逻辑阶段的网络尝试、格式修复、端点切换及备用路线共用最多5次额度，防止多层各重试5次而放大成25次。不同章节、论证单元或核验批次分别拥有自己的额度。

已收到部分输出或远端执行结果未知的请求仍保留待核实状态，不自动重复收费；凭据错误、预算不足、取消、来源权限撤回及官方API高峰时段禁用等明确限制不靠重复调用绕过。此次没有扩大任务或项目预算，也没有恢复已暂停的整篇任务。

验证包括：前4次失败第5次成功、5次失败后停止、跨端点合计5次、连接失败与格式修复混合仍只有5次HTTP机会、显式1次限制、未知及部分结果不重发、官方时段规则不受重试绕过。所有模型调用使用隔离模拟传输，未为测试产生真实模型费用。
