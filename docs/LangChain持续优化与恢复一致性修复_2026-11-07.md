# LangChain 持续优化与恢复一致性修复

本轮接续 [首轮修复记录](LangChain审计问题修复与验收_2026-11-07.md)，重点修复策略随续跑变化、证据分类残留分歧、未知请求统计及运行状态不真实的问题，并减少重复构图和失败后启动的检查。

## 本轮改动

| 方面 | 实际行为与代码位置 |
| --- | --- |
| 写作策略快照 | `ai_runtime/policy.py` 在任务创建时冻结 writing_flow 的核验开关、修订上限、取材限制、分单元阈值等值；`writing_flow.task_settings()` 贯穿准备、生成、语义核验、篇章检查、重复检查和修订阶段。修改设置只影响新任务 |
| 子任务与有据写作继承 | 同项目内部子任务继承父任务快照；有据写作后继步骤沿用会话首个步骤的设置。旧任务没有快照时保留兼容规则，不推测或伪造当时参数；其后继也不自动补成当前值 |
| 快照校验 | 保存设置与校验快照复用相同的字段、类型和范围约束；完整快照缺字段、含未知字段或类型错误时拒绝入队，事务回滚不留下孤立任务 |
| 证据分类一致 | 选材、原文绑定与展示标签共用分类依据。普通 planned 事实不再被当成测试定义；关联了真实执行产物的 measured 事实会读取产物原始记录，从而正确进入 run_result 候选 |
| 请求统计诚实表达未知 | 缺少实际尝试记录时，actual_sends / retries / endpoint_switches 返回 null；单独保留 observed_send_starts 与覆盖状态。仅凭没有发送事件不再推断发送前拒绝；发送开始记录也不冒充服务方已接收证明 |
| 对照参数完整性 | 即便模型身份相同，缺失实际输出额度等必要参数时也返回 model_parameters_unknown，不把两个未知参数配置当成已受控配对；请求关联查询去除了一次重复读取 |
| 运行能力诊断 | 新增 `ai_runtime/health.py`，实际检查 Runnable、工具、检索器、图、SQLite saver 和追踪控制能否加载，检查点按只读方式检查。损坏检查点或缺依赖时返回实际不可用状态，前端展示原因 |
| 安全复用适配器 | 模型 Runnable 与有据写作的无状态路由图按进程复用；传输函数、任务、消息和结果仍按次传入，不在缓存中保存。章节图包含任务闭包，继续按运行建立，避免串用状态 |
| 并行失败处理 | 独立检查按完成顺序观察结果；失败时停止尚未开始的检查。已启动的检查仍会被观察，未知远端结果仍优先报告；共享事务或尝试预算时继续串行 |

没有增加模型传输层、网络重试层或自动付费评测。模型端点、请求容量、费用及来源权限继续走原有实际发送前检查。

## 生效与边界

- 源码和前端产物已更新，重启工作台与执行器后加载；本轮没有停止当前正在运行的实例。
- 新任务记录完整写作流程快照；历史任务缺少快照时仍按原兼容方式执行，不能把当前值冒充历史值。
- 依赖加载结果按当前进程缓存，环境修复后需重启以刷新；检查点诊断仅确认可读性，明确返回 write_verified=false，不声称已完成写入验证。
- 测试使用隔离数据库、合成传输及临时检查点，没有调用收费模型或改写当前用户论文和数据库。
- 原生模型契约、章节图分支重构、跨版本图迁移及历史归档仍是独立的后续工作，不由本轮测试代替验收。
