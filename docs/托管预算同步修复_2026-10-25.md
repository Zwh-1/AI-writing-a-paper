# 托管预算同步与恢复修复

2026-10-25。

## 问题与行为

- 可用额度变化后，未手动编辑的本轮预算随最新额度更新，按分向下取整。例如可用 1.0588556 USD 时，显示与可填写上限均为 1.05。
- 手动填写的上限保留；超过可用额度时提供“使用当前可用预算”操作。运行中的已授权上限不因费用增加而被改写。
- 提交前后端在同一事务中检查当前可用额度。额度已变化时返回 409 及最新余额，前端刷新输入并显示原因，不创建新任务或改写原策略。
- 新增资料自动接续时，单轮预算不超过原授权上限及当前可用额度。低于一分钱时等待预算，不创建无预算任务。
- 账单核对失败（包括 HTTP 403）显示实际原因，保留原费用预留；不再提示核对成功或自动重复模型请求。
- 修复规则详情的未定义预算变量；详情账单操作使用任务的模型路线，核对后刷新预算。
- 后台预算等待任务仅在项目余额、本轮限额、GPT 子预算均能覆盖下一次完整请求预留时恢复，避免正余额触发反复失败。

## 验证

53 项后端回归通过，范围包括托管、预算、任务摘要和账单。

浏览器隔离夹具验证了额度下降、保留手动输入、一键修正、账单 403、提交瞬间额度变化、重复点击、运行预算、切换项目、低于一分钱及手机布局；无页面错误，无付费模型请求。前端生产构建通过。

测试入口：tests/test_autopilot_budget.py、tests/autopilot-budget-browser.cjs。

## 边界

预算同步修复不表示未完成资料或规则已经审核通过。服务方账单权限、原文缺项、未知执行结果及未决规则继续保留，不能靠增加完成率、重置费用或扩大项目预算绕过。
