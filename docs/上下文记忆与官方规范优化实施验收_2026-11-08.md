## 上下文与记忆的具体规则

### 论文正文

1. `full_manuscript` 继续完整读取全部已保存正文，作为兼容默认值；容量不足时明确停止。
2. `hierarchical_v1` 完整读取当前章与递归依赖。依赖不存在、已归档或形成循环时拒绝继续准备。
3. 其他章节导航来自作者原文的完整段落，保存章节 ID、正文版本、段落位置、内容哈希和遗漏说明，不生成虚构摘要，也不把导航提升为事实证据。
4. 有据写作通过 `read_section`、`read_section_range` 和文献阅读工具补读明确原文；后续普通写作已增加独立章节阅读阶段，最多两轮，保存实际补读范围并重新校验预算和权限。未读目录仍不能声明为全文已通读。
5. 全文与分层模式都守卫相关章节版本、提纲、术语和来源权限；分层模式没有放宽权限检查。为保持一致性，目前仍保守核对未完整提供章节的来源权限。
6. 可选导航先于必要正文延期，实际读取范围、延期内容和记忆排除原因进入清单。界面区分完整正文与目录导航。

### 项目记忆

- 复用已有版本随记与内容对象，不新增平行记忆数据库，不需要为本轮记忆功能额外迁移数据库。
- 记忆不是研究证据。作者决定表达作者意图；工作假设和待解问题保留未验证状态；导航只帮助回查原文。
- 新任务固定记忆政策、候选条目版本和内容哈希。后来新增的决定不会悄悄进入旧任务；原条目编辑、删除、被替代或来源撤权后，会排除旧条目，已准备的请求及采用阶段还会重新验证。
- 同主题的多个有效作者决定被列为冲突，不自动采用“最新一条”。可明确勾选替代旧决定，历史版本继续保留。重复保存同一决定仍能处理明确指定的替代关系。
- 编辑已有记忆保留来源与章节版本绑定，避免修改文字后丢失来源约束。章节正文变化后，关联记忆会过期；重建导航创建新版本并替代旧导航，不调用模型。
- 界面每页最多展示 100 条；检索和任务快照覆盖全部有效记忆，已去掉原来只读取最近 500 条的内部限制。界面页码不会使较早的作者决定消失。
- 默认记忆输入预算为 10,000 UTF-8 字节，整条选择，不截断条目；按作者决定、当前章关联和词面相关性排序。延期与冲突分别记录，不能把延期理解为冲突已解决。
- 任务继承先读取父任务的冻结政策，再准备子任务。继承过程中不重新发现当前技能目录、当前记忆或写作设置。普通非写作任务也不再重复构建两次相同快照。

### 会话历史

- 默认保留最近 16 条消息，历史输入预算 16,000 字节；只取实际待回复消息之前的连续后缀，并从用户轮次开始。
- 容量允许时，保留少量早期用户完整原话作为有消息 ID 的会话记忆，明确其只是先前请求，不代表已执行、已确认或事实依据。
- 逐项列出未提供的消息。更早消息超过查询窗口时，另行报告未加载数量，不声称已经通读全部会话。
- 权限检查覆盖本次真正提供的最近消息和早期原话；未发送的旧助手回复不会因来源撤权阻断无关新请求。实际提供的旧内容仍受权限、消息版本及发送前、响应后校验约束。
- 通用研究对话当前只存用户与助手消息；原生写作 agent 的 tool call/result 历史继续由其专用适配器保持配对，没有交给该文本历史压缩器处理。

## 使用入口

1. 打开“写作流程与论证计划 → 流程设置 → 论文上下文范围”，选择全文或分层模式，保存后应用于新任务。
2. 打开同一区域的“项目记忆与技能”。可新增、编辑、移除记忆，绑定章节版本，重建导航，明确替代冲突决定，调整输入预算并选择技能。
3. 选择需要核对的章节，点击“预览所选章上下文”。显示完整章节、目录章节、记忆数和衔接层保守估计；实际写作还要加入规则、证据、技能与输出契约，以最终发送检查为准。
4. “全文与分层模式效果对照”接受同一项目已有任务编号，只读取记录、不发起模型请求。同一正文、来源、记忆和其他设置才可配对；接口、模型参数、来源或其他控制项不一致时保留不能比较状态。引用支持率、遗漏和作者修改量不自动代填。
5. “上下文运行记录”可查看 30 天前已结束任务的归档范围，归档后可以恢复。没有执行自动删除。
6. “核查与交付 → 多格式导出 → 论文标准与参考文献校验”设置标准版本、学校要求、正式来源、条款性质和规范冲突处理决定。未解决冲突阻止正式导出。
7. “论文图表 → 最终排版尺寸与图中文字要求”设置宽度、文字和 DPI。保存后可下载 SVG/PDF，导出报告按实际放置宽度复核。统计图入口使用 CSV/XLSX 的实际数值，保留排除行、分箱及上下界说明。
