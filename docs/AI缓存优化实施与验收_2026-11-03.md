# AI 缓存优化实施与验收

本记录对应《AI请求缓存优化方案_2026-11-03.md》的代码实施。新代码不自动重启服务器或后台工作进程，不修改已有任务的布局、不重算历史账单、不清理未知请求，也不新增付费预热请求。生产进程需要在后续完整重启后才能加载新逻辑；当前任务继续按原进程执行。

## 已实现的行为

| 范围 | 实现 |
|---|---|
| 请求布局 | 新写作任务冻结 `cache_v2`；规则、术语、已选原文等稳定字段前置，单元/字数/批次/修复错误置于动态尾部。历史缺少版本字段的任务使用 legacy。 |
| 原文与引用 | 先规范已声明无序的材料集合，再运行既有可逆文本压缩；不排序段落、工具历史或 Responses items；事实表审计时间仅从模型视图投影移除。 |
| 普通和智能体请求 | 普通写作、整篇写作和 agent_step 接入；native agent 工具 frame、别名、消息顺序保持。修复 system 固定，诊断参数放入数据。 |
| 用量统计 | Chat/Responses、普通/pool/stream/agent 统一返回 input/output/cache hit/cache miss/reporting/raw；bool、负数、冲突及缺失保持未知；不从 cached_tokens 推断总输入。 |
| 计价 | 无可验证缓存分价时维持原保守估算；有分价时要求端点、模型、币种、版本、单位和当前凭据匹配。不套用未经核实的优惠。 |
| L1 材料缓存 | 128项及32 MiB双上限，按UTF-8计容量；命中返回深拷贝，超大单项不入缓存。只缓存材料视图，不缓存权限或完整生成结果。 |
| L2 响应恢复 | 写作完整响应仅在同task内复用；语义键含布局、模型视图、生成意图和输入版本。旧hash/精确wire兼容路径保留；更换恢复端点不要求重生成完成阶段。 |
| 单飞 | 普通写作按数据库/项目/任务/章节/阶段/位置锁定；agent阶段同样串行，并单独保存轮次位置。线程共享锁实例，进程共享FileLock路径；内容或attempt变化不能换锁绕过未确认请求。 |
| 未知与权限 | 获取锁后重新检查代次、租约、取消、来源与权限；先阻断未确认请求，再比较缓存键。等待者也重新校验。未知状态、锁释放或TTL均不授权再次收费。 |
| 实际路由观测 | 成功/部分响应保存实际provider_snapshot、实际凭据摘要、wire fingerprint、布局及稳定/动态块指标。原始记录保持可追溯，不新增敏感全文日志。 |
| 辅助索引 | 新增非唯一任务/时间、知识缓存键、请求哈希索引；知识OR查找拆为两个索引查询并去重。仅初始化且队列空闲时安装，或用维护工具安装/移除，不改user_version。 |
| 数值检索 | 结构单元检索新增归一化矩阵LRU、向量化dot及unit-max聚合。每次仍重新检查eligible、原文和当前向量版本。可关闭回退scalar计算。 |
| 既有路由约束 | DeepSeek安全失败后GPT接替、独立次数上限、同任务保持GPT、任务间隔离、官方总授权/高峰限制及预算检查全部保留。 |

模型材料块可在同一数据库和项目内复用相同纯数据，不共享完整模型响应或权限判定。完整写作响应的复用严格限定task ID。数值矩阵只保存数字、ID和版本摘要。

数值缓存有两类独立池：原sources矩阵与新增结构单元矩阵各最多8项、96 MiB，合计最多192 MiB矩阵数据；加材料块32 MiB，以上几类缓存的保留数据上限合计224 MiB，不代表整个Python进程的内存上限。原有query/rerank缓存容量未变。

## 改动文件

核心模块：

- `backend/app/ai_cache_policy.py`：默认值、配置校验、API、任务创建时冻结版本。
- `backend/app/prompt_layout.py`：确定性模型视图、材料顺序范围、固定system及块指标。
- `backend/app/ai_request_cache.py`：有界LRU、任务内语义键、实际请求键、稳定位置单飞锁。
- `backend/app/ai_cache_indexes.py`、`scripts/manage_ai_cache_indexes.py`：仅空闲维护辅助索引。
- `backend/app/tasks.py`、`writing_flow.py`、`writing_request.py`、`document_preparation.py`：普通/整篇调用接入、实际预算、恢复与发送边界。
- `backend/app/adapter.py`、`provider.py`、`provider_stream.py`、`writing_agent/provider_adapter.py`：用量/传输一致、智能体布局与单飞、实际路由及计价。
- `backend/app/knowledge_model_bridge.py`：持久响应查找索引化，保留原知识缓存语义。
- `backend/app/retrieval.py`、`knowledge_service.py`：结构单元数值矩阵缓存。
- `backend/app/summary_billing.py`、`writing_agent/billing.py`、`rule_review_receipts.py`：统一缓存用量，未知不假报0；`frontend/src/Completion.tsx`显示未知缓存用量。
- `backend/app/db.py`、`api/routers.py`、`api/v2/registry.py`及生成的API映射/清单：空闲索引与设置入口。

未引入Redis，未开放写作跨任务完整响应缓存。服务商可选缓存提示参数保持关闭；没有已验证能力时API拒绝启用，不向DeepSeek或中转站强加参数。

## 配置与回退

设置接口：`GET/PUT /api/v1/ai-cache-policy`，规范入口 `GET/PUT /api/v2/model-providers/cache-policy`，沿用应用原有本机会话和CSRF校验。

```json
{
  "new_task_prompt_layout": "cache_v2",
  "stable_block_lru_enabled": true,
  "task_recovery_v2_enabled": true,
  "writing_singleflight_enabled": true,
  "unit_matrix_cache_enabled": true,
  "provider_cache_hints_enabled": false
}
```

只回退新建任务布局与可选缓存时，PUT以下部分更新即可；没有列出的设置保留：

```json
{
  "new_task_prompt_layout": "legacy",
  "stable_block_lru_enabled": false,
  "task_recovery_v2_enabled": false,
  "unit_matrix_cache_enabled": false
}
```

这不会改写在途/暂停任务的布局，仍保留其旧版本实现及旧恢复缓存。单飞不能通过API热关闭；必须先排空在途请求并恢复明确串行约束后再进行离线维护。不能把单worker误当作没有线程并发，也不能删除pending/sent/outcome_unknown来解除阻塞。

辅助索引检查是只读的，可在运行期间执行。安装/移除命令会检查queued/running任务及pending/sent请求，非空时直接拒绝；保持SQLite user_version和所有账本记录。

在仓库根目录使用 `pwsh.exe`：

```powershell
if ($PSVersionTable.PSVersion -le [version]'7.6.0' -or $PSVersionTable.PSEdition -ne 'Core') { throw 'Requires PowerShell > 7.6.0 Core' }
& '.\.runtime\python\python.exe' -X utf8 '.\scripts\manage_ai_cache_indexes.py' --check
# 后两条仅在空闲维护时选择其中一条执行，不能在运行写作时执行：
# & '.\.runtime\python\python.exe' -X utf8 '.\scripts\manage_ai_cache_indexes.py' --install
# & '.\.runtime\python\python.exe' -X utf8 '.\scripts\manage_ai_cache_indexes.py' --remove
```

本机只读检查已显示 `SEARCH generation_runs USING INDEX ai_cache_task_created (task_id=?)`，没有该查找的临时排序；user_version仍为17。历史截图报告保留原审计时的SCAN基线，不把前后查询计划混为同一时间状态。

## 验收与收益边界

新增测试：`test_ai_cache_usage.py`、`test_ai_prompt_layout.py`、`test_ai_cache_policy.py`、`test_ai_request_singleflight.py`、`test_ai_agent_cache.py`、`test_ai_cache_indexes.py`、`test_ai_unit_matrix_cache.py`。另保留审计工具的 `test_audit_ai_cache.py`。

验收覆盖：

- 100组字段/材料排列及跨进程hashseed：模型字节及稳定块摘要一致。
- 100组单元、字数与修复诊断：固定system和共享材料前缀一致，差异在动态尾部。
- 两线程同阶段一次发送/一次预留；不同输入不能并行绕过；跨进程FileLock排他。
- 命中完成响应后HTTP及新预留均为0；不同task不共享响应。
- 原文、权限、规则、模型视图及生成意图变化正确失效；单改恢复端点仍可使用完成响应。
- pending/sent/unknown/partial即使改输入或追加消息也不重发；等锁期间取消或撤销权限立即阻止。
- 各协议/传输统一用量契约、实际路由和凭据归属、未知/冲突计数、缓存分价证据。
- 数值排序与scalar一致；NaN/零向量/维度/模型/原文/向量更新、权限和数据库隔离。
- 索引安装、撤回、同名外来索引保护、空闲检查和数据库版本/账本保持。
- GPT自动接替、官方策略、格式修复、整篇恢复和API兼容。

最终29文件联合回归 **643项全部通过**，0失败、0错误；报告：`.runtime/diagnostics/ai-cache-implementation-final.xml`。补充边界报告：`.runtime/diagnostics/ai-cache-final-boundaries.xml`（61项）、`.runtime/ai-cache-version-final.xml`（57项）、`.runtime/ai-cache-key-versions.xml`（3项）、`.runtime/ai-cache-agent-final-incremental.xml`（16项），均通过。各报告用例有重叠，不累加成独立测试总数。前端 `npm run build --prefix frontend` 已通过TypeScript与Vite生产构建；保留原依赖弃用及bundle大小提示，没有构建错误。

所有模型测试使用隔离库与模拟传输，没有额外的真实收费测试。`docs/ai-cache-audit-20261103-15-16.json`和对应Markdown仍是截图对齐的历史基线：命中26.79%、未命中2,198,197。60%命中率对应未命中输入减少约45.37%是后续同类负载的观测目标；本次离线验收不等于服务商已实现该命中率或已节省相同比例账单。
