# 核心写作与素材闭环实施记录

日期：2026-11-03。对应[核心写作优化方案](D:/桌面/论文/paper-workbench/docs/核心写作能力深度优化方案_2026-11-03.md)和[素材驱动写作方案](D:/桌面/论文/paper-workbench/docs/素材驱动AI写作闭环改造方案_2026-11-03.md)。本轮交付为工作区源码和已构建的前端，不表示历史安装器、便携包或正在运行的旧后端已经自动升级。

## 实现范围

普通单章、整篇生成、定向修改/扩写/压缩、编辑器补全以及有据写作共享素材服务和来源政策。语言润写保留独立保真契约，不自动添加事实；需要补证或改变论证时使用定向修订。

默认流程：章节问题/论证卡 → 规则与素材检索 → 原文读取和冻结依据包 → 候选生成 → 主张级核验 → 有限轮次补证修订 → 审阅采用。较长新章节按论证单元生成并保存检查点。

| 功能 | 实现位置 | 行为与边界 |
| --- | --- | --- |
| 共享素材发现、读取与回执 | writing_retrieval.py、writing_retrieval_api.py | 区分约束、原始依据、指导与派生材料；实际读取范围、版本、权限和轨迹密封保存；客户端预览不授予已读身份 |
| 历史阅读补齐 | document_preparation.py、guidance_preparation.py | 空阅读和旧阅读不再屏蔽新命中文献；读取指导正反例时保留教学语境 |
| 论证计划与状态 | writing_argument.py、writing_flow_api.py | 复用命题和argument_edges，生成任务卡，支持作者编辑；全文模式保留，可显式选论证范围模式并展示未读范围 |
| 生成与恢复 | writing_flow.py、writing_tool_runtime.py | 长章节按完整论证单元生成；复用已完成请求/单元；远端未知结果不自动重发 |
| 动态取材 | writing_tool_runtime、writing_agent.tools/coordinator | 复用native/JSON工具循环，发现缺口后补读；文献工具不再强制代码快照，代码工具仍校验授权基线 |
| 精确引用 | schemas、writing_evidence_quality、drafting、documents | claim_spans/citation_intents绑定原句与原文；验证后插句末原生引用，复用引用、句子与命题关系 |
| 成果等级保真 | writing_evidence_quality.py | 区分源码、测试定义、真实执行/导入记录、计划事实及作者说明；data_result名称不授予实测资格 |
| 核验与修订 | writing_flow._semantic/finish及既有verification | 独立检查主张、原文摘录、条件、任务点和衔接；最多2轮修订，保护正确原句和精确引用；未覆盖不计通过 |
| 项目内重复检查 | writing_originality.py | 章内、跨章及已读来源的字面匹配和可选本地向量召回；区分引文、术语和必要回顾，不换算商业查重率或AIGC率 |
| 采用守卫 | tasks、paper_writing、adoption、impact、provenance | 发送、恢复和采用均校验来源/规则/材料集合及版本；关键引用映射或成果等级错误不能绕过采用 |
| 前端入口 | EvidenceTrace、WritingFlowControls及原写作页面 | 显示检索、已读、已用、缺口、修订及论证卡；可保存流程设置与逐章论证计划 |
| 本地性能 | retrieval.py | 归一化矩阵缓存、向量化TopK、稳定并列排序、每模型推理锁；缓存命中仍复验权限 |

复用现有数据库结构，不新增迁移、不重置用户项目、密钥、正文或原件。轻量取材会话默认不挤占正文写作会话列表，可通过include_materials查询审计记录。

## 使用与接口

整篇开始页新增“素材与写作流程”设置，可调整语义核验、重复检查、上下文范围、轮次、工具额度和单元篇幅。逐章论证卡可加载、编辑并保存，后续生成使用当前有效作者计划。

默认值：全文上下文；长章阈值2600字；单元目标1000字；最大2轮补证修订；每章共享12次工具调用、单次调查最多4轮；素材读取预算24000字符。实际请求仍受所配置模型容量、项目/整篇/会话费用上限约束。

候选中展开“素材与写作核验”可查看实际原文、定位和未决事项，并沿既有产物导航回查。补全以原生节点插入引用，版本过期或存在阻断映射时不能直接插入。

| 功能 | 兼容v1业务路径，v2经统一注册表映射 |
| --- | --- |
| 流程设置 | GET/PUT /projects/{pid}/writing-flow/settings |
| 观测指标 | GET /projects/{pid}/writing-flow/metrics |
| 论证计划 | GET/PUT /projects/{pid}/writing-plan?section_id=... |
| 素材操作 | POST /projects/{pid}/writing-retrieval/search、prepare、read、validate |
| 候选报告 | GET /projects/{pid}/writing-quality/{tid}?section_id=... |

新增接口已导出到api-contract-v2.json及前端映射。费用只基于本地实际账本，未知费用单列；没有对照基线时不输出效果提升百分比。

## 验证与边界

使用隔离数据库、合成原件和模型回复验证，没有对用户论文执行生成或商业检测，没有新增外部模型费用。验收服务采用独立端口和数据目录，原有工作台服务未参与测试。

专项覆盖：无手选文献的普通写作、结构化知识单元经过压缩后的版本保留、整篇候选、动态工具补证、精确引用、正确主张保留、预算/取消/未知结果、权限撤回、来源变更、普通及部分采用阻断、历史引用保留和多次显式原文读取。

全量后端回归初轮1781项通过，发现1项整篇修订保留历史引文来源的问题，已经修复。修复后的核心写作回归232项全部通过，后续读取范围与工具复测45项全部通过，覆盖该初轮失败用例。汇总脚本按实际JUnit用例身份核对所有初轮失败均已有通过复测，结果保存在.runtime/writing-final-acceptance.json；没有将初轮报告改写成全部通过。

HTTP验收通过5组：设置读写、计划连续保存、检索/读取/冻结校验、整篇带来源与报告、动态补证和修订。实际使用14次合成模型回复，外部模型调用0。报告：.runtime/writing-flow-ui-acceptance/http-report.json。

真实Tiptap/ProseMirror检查通过：两类编辑器JSON保存/编辑/重载保留映射；补全引用和sourceRefs保留；Unicode前缀偏移正确；过期或阻断补全不改正文。报告：.runtime/writing-flow-ui-acceptance/editor-report.json；可运行tests/writing-evidence-editor.cjs复测。

TypeScript检查及生产构建通过。浏览器连接不可用，未宣称完成点击、响应式截图或视觉验收；HTTP和真实编辑器交易测试不替代这部分。

合成检索微基准：10,000条、128维、Top40、7次中位数，包含当前向量有效性核对的数值阶段由87.498ms降至30.556ms，结果一致。该数字排除SQL和模型推理，不能推广成整体写作提速65.08%。真实模型的论证质量、人工补引时间及单位合格输出成本仍需固定材料和人工盲评另行测量。
