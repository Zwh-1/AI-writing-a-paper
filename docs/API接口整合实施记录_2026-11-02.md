# API 接口整合实施记录

日期：2026-11-02，Asia/Shanghai。

## 已交付的接口层

主工作台与独立协作服务均支持 `/api/v2`。所有现有业务接口通过一份注册表映射到统一路径，保留原处理函数的权限、预算、幂等、来源核验和业务事务。前端 JSON 请求、图片、下载和 SSE 使用同一个 URL 构造器；协作页面的映射由同一注册表生成，继续使用独立端口与独立登录。

当前运行时注册表覆盖主应用 **458 个方法/路径组合**、协作应用 **27 个组合（包含 WebSocket）**。这些是旧业务入口数，不把 v2 别名重复计数；协作的静态首页和根健康检查另行保留。原方案的 474 条是初步正则扫描结果，遗漏了部分空后缀路由；当前以 [实际接口映射清单](api-contract-v2.json) 和 `/openapi.json` 为准。

接口层已完成统一；SQL、领域状态机与 provider 适配器仍在已有模块内复用，没有将所有业务实现重新搬迁。不同知识系统和写作流程保留自己的语义，路径分组不会把它们误当成同一种数据。

## 公共返回约定

普通 JSON：

```json
{"data":{"id":"..."},"meta":{"request_id":"req_...","api_version":"v2","service":"workbench","generated_at":"..."}}
```

集合：

```json
{"data":{"items":[],"next_cursor":null,"total":0},"meta":{"kind":"collection","request_id":"req_...","api_version":"v2","service":"workbench"}}
```

`total` 是当前业务处理器返回集合的数量，保留已有业务筛选和数量限制。当前门面不伪造全库分页；`next_cursor` 固定为 `null`。需要大列表分页时应在对应领域服务实现真正的数据库分页。

任务：

```json
{"data":{"task":{"id":"...","kind":"review","status":"queued","progress":0},"links":{"self":"/api/v2/tasks/...","events":"/api/v2/tasks/.../events"}},"meta":{"kind":"task","request_id":"req_...","api_version":"v2","service":"workbench"}}
```

错误（包含认证、CSRF、校验和业务异常）：

```json
{"data":null,"error":{"code":"UPSTREAM_ERROR","message":"...","details":null,"retriable":false,"unknown_outcome":true},"meta":{"request_id":"req_...","api_version":"v2","service":"workbench"}}
```

- `X-Request-Id` 接受不超过 128 字符的安全标识，否则生成新值；响应头与 JSON 中保持一致。
- `Headers`、CSRF、`Idempotency-Key`、外部取消信号与超时由统一客户端处理；客户端不会自动重发收费请求。
- 现有幂等键、基础版本、费用确认参数原样传给业务处理器；本次没有擅自添加一套与现有事务冲突的通用写入重试策略。
- 未知执行结果不会因为 HTTP 5xx 被标成可重试；未捕获的写入异常也保留结果未知提示。
- FastAPI 校验错误仅返回字段位置、类型和错误信息，不回显提交的密码或密钥。
- 含 `Content-Disposition` 的 JSON 凭证下载、二进制文件和 SSE 不包 envelope；Cookie、多值头、ETag、后台回调与流式帧保留。
- 普通 JSON 中明确标注为下载/预览的链接同步转换为 v2；正文与来源字符串不做全局替换。
- `/api/*` 未命中时返回 JSON 404，静态前端回退只处理页面地址。

## 当前目录与维护方式

```text
backend/app/api/
  routers.py              # 旧业务 router 的集中挂载与所有权
  v2/
    __init__.py           # 在认证 middleware 外安装统一契约
    registry.py           # 唯一路径映射、参数命名、领域分组与 OpenAPI
    contracts.py          # 成功、集合、任务和错误结构
    middleware.py         # ASGI 适配，保留下载和事件流
frontend/src/api/
  client.ts               # 请求头、取消、超时、解包、错误
  paths.ts                # 唯一 URL 构造器
  routes.generated.ts     # 从后端注册表生成，不手动编辑
  types.ts                # 公共契约类型
  projects.ts / writing.ts / providers.ts / knowledge.ts / tasks.ts
frontend/src/client.ts    # 旧组件导入的兼容出口
scripts/export_api_contract.py
docs/api-contract-v2.json # 可评审的方法、路径、领域、owner、transport 清单
```

新增功能先在领域 router 定义业务处理器，再在 `registry.py` 维护必要的统一命名。执行 `scripts/export_api_contract.py` 同步前端映射和 JSON 清单，运行契约测试核对所有路由。不要手工修改生成清单，也不要在页面中写 API 版本前缀。

## 调用示例

```ts
import { api, request, apiUrl } from "./api/client";
import { writingApi } from "./api/writing";

const sessions = await writingApi(projectId).sessions();
const files = await api(`/projects/${projectId}/files`); // 集合自动解包为数组
const full = await request(`/tasks/${taskId}`);         // 保留 data/meta/links
const download = apiUrl(`/files/${fileId}/download`);  // 也用于 img / EventSource
```

原组件 `api('/projects/.../writing-sessions')` 也会经生成映射调用新的 `/writing/sessions`。因此旧组件逐步迁移到领域客户端时，已经使用相同的公开接口契约。
