# 全部资料与规则重新生成

日期：2026-10-26。

本次处理针对用户指出的旧规则包 V32（789 条生效规则、1840 条提取记录）。之前的文献阅读升级不会自动重建这些既有规则；规则提取仍使用旧的来源分段和检查点。因此新增按完整原件生成新规则代次的流程，并在真实资料上执行全量更新。

## 已实施的流程

1. 先备份数据库，保留原件、既有来源、旧规则及规则包快照。
2. 对全部 57 个启用文件按原页重新建立结构版本，刷新本地索引。本轮新增索引窗口 13,071 个，模型为已安装的本地 BGE；不调用付费生成。
3. 对 24 份规范资料读取完整幻灯片、原页和独立标识的转录候选。评分 PDF 另外读取带等级、表头及跨页关联的完整标签行。
4. 初始范围为 1,169 个原文单元、165 个批次。目录用于选择补读范围，模型可以请求同一文件中的远处单元；预算不足时不能截断或冒充完成。
5. 新代次使用独立检查点，不复用旧的片段提取结果。已完成的本轮模型响应可以复验并复用；未知远端结果不会自动重发。已明确返回不完整 JSON 的批次，按完整原页或幻灯片拆成更小批次处理。
6. 所有批次成功后才原子切换新目录。旧条款仍保留在数据库与历史快照中，当前目录通过代次设置排除已退役条款，手工新增要求继续保留。
7. 通过已有发布检查后生成新规则包。若来源、权限或结构版本在处理期间变化，不能采用旧范围的结果。

## 语义与引用边界

- 引文可恢复排版空白差异，但必须映射回实际原文；保存实际字句。
- 模型对条件的解释与条件原文分开。无法在原文定位的条件不能直接升级为已验证约束。
- 无法定位的模型引句不会成为规则陈述；完整原页以待核对候选保留，模型置信度不被当成事实。
- 教学正反例、OCR 转录及评分等级分别处理。课程指导默认建议；评分条件不自动变成项目必须达到的等级。
- 原文处理覆盖、机器用途判断、人工语义审查分别记录，不代填人工确认。
- 新的规则上下文来源是派生记录，不能反过来改变原件解析指纹或被重复提取成新规则。

## 界面与接口

“论文规则”页面增加“按原件重新生成规则”区域，显示批次进度、异常和新规则包，并可查看 V32 等历史快照。

- `GET /api/v1/projects/{pid}/rules/rebuild`：读取最新重建进度。
- `POST /api/v1/projects/{pid}/rules/rebuild`：在项目可用预算内重建；可传 `resume_task_id` 续接同一代次和费用账本。
- `GET /api/v1/projects/{pid}/rules/rebuild/history`：列出历史规则包。
- `GET /api/v1/projects/{pid}/rules/rebuild/history/{id}`：读取指定项目的固定快照。

自动重建调用使用者已配置的主模型并计费；项目总预算不因重建而增加。模型处理长响应、条件解释或原文争议时，仍可能保留待核对项。

本机记录位于 `.runtime/full-file-refresh.json`、`.runtime/rules-rebuild-plan.json` 和 `.runtime/rules-document-live-task.json`。更新前备份为 `data/backups/before-full-file-refresh-20261026-182119.sqlite3`。
