# 写作全流程编排与上下文策略 V1.0（2026-10-31）

这份文档回答四个问题：每一类写作操作里模型按什么顺序做、能看到什么、依据什么推理、失败时怎么收场。对应的实现是 `backend/app/writing_ops.py`（操作注册表）与 `writing_brief.py`（任务书）、`writing_checks.py`（自检），四类场景共用同一张表，提示词、上下文装配、参数与接口都从这张表取，避免各写一套。

设计上有意不给模型一段“请先思考再回答”的自由推理：推理被拆成**程序生成的任务书**（覆盖点、段落计划、依据提示、禁止项）和**程序执行的自检**（覆盖、锚定、篇幅），模型只负责在给定框架里写。这样每一步都可核对、可计费、可回退，也不会因为隐藏的思考过程产生无法解释的请求。

## 一、统一编排模型

每个操作由三个阶段组成：程序准备（读本地记录、算预算、给任务书）→ 模型起草（只输出候选，不写正文）→ 程序核对（结构、依据、篇幅、重复）。失败一律停在“候选”这一层，不会半截写入正文。

| 操作 | 内部 kind | 规则类别 | 输出契约 | 主要自检 |
| --- | --- | --- | --- | --- |
| 整篇论文生成 | write_paper | generate | 段落数组 + missing_materials + visuals | 覆盖点、依据锚定、段落计划、篇幅、跨章重复、数值漂移、术语写法 |
| 单章生成 | write | generate | 同上 | 覆盖点、依据锚定、段落计划、篇幅、跨章重复、数值漂移、术语写法 |
| 定向修改 | write | revise | 段落数组 + preserve_node_id | 覆盖点、依据锚定、选区未越界、数值漂移、术语写法 |
| 扩写 | write | revise | 段落数组 + preserve_node_id | 覆盖点、依据锚定、篇幅、数值漂移、术语写法 |
| 压缩 | write | revise | 段落数组 + preserve_node_id | 覆盖点、篇幅、术语写法 |
| 学术润写 | write | polish | source_node_id + text（含占位符） | 段落对应、占位符、数值、限定词、篇幅变化 |
| 图表生成 | paper_visual | — | spec + missing_materials | 类型约束、标签落地、缺口清单 |

## 二、四类写作场景

### 2.1 整篇论文生成

**前置**（`paper_writing.preflight`）：提纲非空且依赖无环、规则包已发布、所选接口有密钥、单次费用可预留、项目预算足够；任一不满足只返回阻塞项，不发请求。预览里同时给出每章的字数、占比、已有正文、依据条数与段落计划。

**阶段**

| 阶段 | 执行者 | 做什么 | 产物 |
| --- | --- | --- | --- |
| brief | 程序 | 逐章生成任务书：覆盖点来自章节目标（拆句）或类型模板，研究问题进入绪论/结论/摘要，段落计划按目标字数分配职责，依据提示只给已登记的事实与已提供的原文 | `writing_brief`（含 hash） |
| draft | 模型 | 通读已保存正文与本任务已完成候选，按任务书逐段写，段落回填 `brief_points` 与来源/事实编号 | 章节候选 |
| check | 程序 | 覆盖点是否齐全、数值类论断是否有依据、段落数与篇幅是否接近计划 | `brief_check` |
| review | 程序 | 章节完整、引用结构、摘要对应、跨章重复，合并逐章自检 | 全文问题清单 |
| adopt | 程序 | 核对候选哈希与输入版本，单事务写入草稿 | 章节修订版本 |

**上下文分层**（真实行为，`writing_request.pack` 按此顺序降级）

| 层 | 内容 | 超预算时 |
| --- | --- | --- |
| 必须 | 适用规则、写作任务书、章节任务、项目简报、术语表、研究事实 | 不移除；仍然超限则整体报错并指出占用最大的三项 |
| 连续性 | 当前章正文、其他章节正文、本任务已完成候选 | 保留，保证跨章一致；整篇超出容量时报错而不是摘要替代 |
| 证据 | 原文片段、已读原文单元、派生知识导航、项目代码观察、文献阅读记录 | 按整篇或整组延后，同时写入缺口，禁止截断单条 |
| 参考 | 参考文献表 | 随所属文件一起裁剪 |
| 可选 | 写作指导示例、可复用图表 | 先延后 |

**推理链路**：章节目标 → 覆盖点 → 段落职责分配 → 每段的依据提示 → 写作 → 覆盖与锚定核对。覆盖点编号（g1/k1/rq）在任务书、模型输出与自检三处一致，缺哪一点可以直接指出。

**资料、规则与正文的调用**：规则按 `operation=generate` 且 `category≠format` 过滤，格式规则交给排版程序；研究事实按登记状态原样发送，未核验的不升级为结论；已保存正文以全文进入，不摘要、不选段；其他章节只读，候选中的正文只作衔接，不作为事实证明；写作指导资料只提供语体范例，不进入事实层。

**失败与继续**：预算或容量中断时保留已完成章节与 checkpoint，处理后可继续；单章响应无法构成候选时保留原始响应并停止，不跳过该章继续写。

### 2.2 单章生成

与整篇共用 brief/draft/check 三段，差异有三点：任务书只针对本节；不读"本任务已完成候选"（没有整篇上下文）；结果只作为候选返回，写入正文走单独的人工采纳接口。自检结论随候选返回，界面可直接看到"覆盖 4/5 点""2 段出现数值但未回填依据"。

### 2.3 定向修改、扩写与压缩

**入口约束**：选区必须是当前正文里的连续段落，且不能包含锁定段落与图文关联段落（后者只能用润写，否则交叉引用会断）。基础版本不一致直接 409，不做猜测合并。

**任务书**：把修改指令、所选审阅问题、选区前后文整理成要求清单；扩写只允许展开尚未覆盖的点，压缩把"必须保留的覆盖点与引用"作为下限。

**推理链路**：先定位问题段落 → 判断该段属于哪个覆盖点 → 只改这些段落 → 正确内容用 `preserve_node_id` 原样保留 → 程序核对选区之外是否被误改。

**联动**：修订范围按依赖闭包扩展，涉及正文变化时结论与中文摘要、英文摘要按顺序重算，未涉及的章节原样保留并记录来源任务。

### 2.4 学术润写

**只改语言**：不新增事实、不改数值与限定、不合并拆分段落。可写范围由程序切分：普通文字段可写，引用、脚注、带格式片段替换成 `⟦PW-…⟧` 占位符，模型必须原样带回。

**语言任务书**：术语中英文对照（取自术语表，最多 12 对）、语体（书面学术）、衔接（指代与承接）、结构（段落数与顺序不变）、篇幅带 0.75–1.3 倍。

**核对**（程序，任一项不过整份拒绝）：段落逐一对应且顺序不变、占位符集合与顺序一致、数值与单位集合一致、否定/条件/完成状态标记一致、可写范围之外未改动；篇幅变化写入结果供复核，不阻断采用。

**全文参照**：默认 `full`，整篇正文以全文进入；容量不足时可把参数 `manuscript_mode` 切到 `outline`，此时其他章节用首句摘要代替并在结果中标明"未通读"，而不是静默失败或假装读过。

### 2.5 图表生成

**来源与权限**：只接受已保存正文的修订版本或既有图表的来源链；正文来源禁外发时直接 403；图表本身设为仅本机时不能发送。

**任务书**：给出可引用的正文摘录、取名规则（节点、实体、字段、表头尽量沿用正文原词）、禁止项（不得出现实验结果、性能数字、通过率、部署状态）、结构不确定时用【待补】。

**类型约束**（`validate_spec`，程序拒绝而不是让模型自由发挥）：流程图 ≤20 节点；用例图 1–4 参与者、1–12 用例，include 由基础指向被包含、extend 由扩展指向基础、association 只连参与者与用例；ER ≤9 实体、每实体 ≤20 字段且必须有关系；三线表 1–10 列、1–100 行、行宽与表头一致。

**标签审计**：拿到候选后逐字比对标签与引用正文/本次要求，未命中的（除"开始/结束/是/否"这类通用词）写入缺口清单，提示人工确认是否为实际设计。这一步能挡住"凭空多出分布式缓存"这类编造。

**编号与呈现**：图题、图号、交叉引用、三线表结构由程序生成；真实结果与截图不允许用结构示意图替代（`figure_standards.PROTECTED`）。

## 三、跨场景的一致性机制

| 一致性维度 | 机制 | 位置 |
| --- | --- | --- |
| 任务书与候选对应 | 任务书整体哈希写入 manifest 与候选结果 | `writing_brief.hash` |
| 术语 | 术语表随请求发送；润写把它列为必须达到的语言目标；写作后逐条核对该术语后的括号英文是否为术语表登记写法 | 注册表 `terminology` 层 + `writing_checks.terminology_gloss` |
| 跨章重复 | 全文检查相同长段落并定位到章节；写作时逐段比对本节候选与已保存章节正文，整段照搬即提示 | `paper_review_checks` + `writing_checks.cross_section_duplicate` |
| 事实数值 | 段落引用了某条事实却写出与记录完全不同的数值，即提示核对；多条事实时合并后再比对，避免误报 | `writing_checks.fact_number_drift` |
| 数值与限定 | 润写逐段比对数值/单位/否定/条件集合 | `polishing.validate` |
| 摘要与正文 | 中文摘要依据本次正文候选，英文摘要按中文摘要逐段翻译并核对数字 | `paper_writing` + `abstract_translation` |
| 图表编号 | 按章节顺序统一编号，交叉引用取实际节点 | `writing_visuals` + `figure_standards` |
| 输入版本 | 整篇任务冻结快照（提纲、规则、事实、文献、术语、正文版本），变化即拒绝沿用 | `paper_writing.frozen_state` |

## 四、安全策略

| 风险 | 控制 | 位置 |
| --- | --- | --- |
| 资料外发越权 | `egress=local_only` 一律不进请求；派生文件沿 `file_derivations` 继承父级限制 | `security.file_allows_remote` |
| 正文来源被撤销 | 生成前逐章检查正文的派生来源，任一章不可外发则整体报错，不静默降级 | `writing_continuity.collect` |
| 规则原件外发 | 规则的来源文件单独校验，禁止外发时 403 | `tasks._writing` |
| 锁定段落被覆盖 | 锁定节点用 `preserve_node_id` 保留；整篇生成前若含锁定的英文摘要则先提示 | `writing_live` + `paper_writing` |
| 选区越界 | 只接受连续段落；选区内含图文关联时拒绝（改用语体润写） | `tasks.writing_preflight` |
| 候选误写正文 | 候选与正文分离，写入走人工采纳；采纳前核对 `paper_hash` 与输入版本 | `paper_writing.accept` |
| 隐藏费用 | 每次请求先做保守预留，价格不明按单次上限，预算不足保留进度 | `summary_billing` |
| 密钥泄露 | DPAPI 加密存储、单行校验、日志与错误统一脱敏 | `security.get_key / redact` |
| 重复扣费 | 幂等键 + 未完成请求需显式确认后才继续 | `tasks.enqueue` / `paper_writing.resume` |
| 全流程可追溯 | 参数修改、采纳、恢复、结转均写审计 | `db.audit` |

## 五、参数配置

参数只影响"怎么排布写作"，不改章节目标字数、单价与模型上限。项目级覆盖存于 `writing_ops:{pid}`，校验通过才保存，并写 `writing_parameters_saved` 审计；非法值或不支持的参数直接 422。

| 参数 | 适用操作 | 默认 | 范围 | 影响 |
| --- | --- | --- | --- | --- |
| paragraph_target_words | 整篇、单章、扩写 | 220 | 80–600 | 段落计划的段数与每段目标字数，也决定自检的篇幅基准 |
| max_paragraphs | 整篇、单章 | 30 | 3–60 | 长章节的段落上限，避免每段只有两三句 |
| cover_points | 整篇、单章、修改 | 开 | 开/关 | 是否要求逐段回填覆盖点；关闭后只做依据与篇幅自检 |
| manuscript_mode | 润写 | full | full/outline | 全文参照的粒度；outline 仅在容量不足时使用并标注未通读 |

一万五千字、九章的常规配置（220 / 30 / 开）下，系统设计与实现章各约 14 段、绪论 9 段、摘要 4 段，段落职责按章节类型分配。参数不进整篇冻结快照（与模型路由同类，属于运行参数），但每份候选都记录任务书哈希与 manifest，改动参数后旧候选仍可追溯到当时的计划。

## 六、接口设计

| 方法 | 路径 | 用途 | 说明 |
| --- | --- | --- | --- |
| GET | `/projects/{pid}/writing-operations` | 操作目录 | 返回七个操作的阶段、上下文分层、自检项、当前生效参数；带 `section_id` 时附段落计划 |
| PUT | `/projects/{pid}/writing-operations/{operation}` | 保存参数 | 只接受该操作声明的参数，逐个校验，返回生效值 |
| GET | `/projects/{pid}/paper-writing/preflight` | 整篇预检 | 阻塞项、警告、章节计划（含段落数与职责）、预算与可用额度 |
| GET | `/projects/{pid}/paper-writing/study` | 写作研判 | 结构、章节依据画像、风险清单、要求草案、费用预估（不调模型） |
| POST | `/projects/{pid}/paper-writing` | 发起整篇 | 需要幂等键与提纲版本；返回任务 |
| GET | `/projects/{pid}/paper-writing/{tid}/review` | 全文审阅 | 问题清单与修订建议，候选哈希校验 |
| POST | `/projects/{pid}/paper-writing/{tid}/revise` | 整篇修订 | 按问题或章节选择范围，联动结论与摘要 |
| POST | `/projects/{pid}/paper-writing/{tid}/resume` | 继续 | 未完成任务续跑，未核实请求需确认 |
| POST | `/projects/{pid}/paper-writing/{tid}/accept` | 整体写入 | 单一事务，任一章节失败整批回滚 |
| POST | `/sections/{sid}/writing-tasks` | 单章写作 | 生成/修改/扩写/压缩/润写，按 `operation` 区分 |
| POST | `/sections/{sid}/accept` | 单章采纳 | 候选写入正文并保留版本 |
| POST | `/projects/{pid}/paper-visuals/ai-tasks` | 图表候选 | 指定类型、来源正文、要求；返回任务 |

主要错误码：`PAPER_NOT_READY`（预检未过）、`PAPER_INPUT_CHANGED`（提纲/正文/规则已变）、`WRITING_CONTEXT_BUDGET_EXCEEDED`（保守上界超容量，附占用明细）、`POLISH_TEXT_REQUIRED`（无可写段落）、`PAPER_REMOTE_ACK_REQUIRED`（继续前需确认可能重复计费）。任务状态为 `queued → running → succeeded | failed | budget_blocked | cancelled | incomplete | outcome_unknown`，后四者可继续且复用已完成部分。

## 八、验证与边界
