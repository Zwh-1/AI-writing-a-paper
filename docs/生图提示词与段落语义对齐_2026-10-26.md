# 生图提示词与段落语义对齐

2026-10-26 修复。此前生图把整章平铺为上下文，图后说明没有进入提示词，新生图也不会使用界面中已经修改的结构；插入依赖编辑器光标，无法保证生成依据与落点一致。

## 使用步骤

1. 在正文里把光标放到需要配图的段落，保存后打开“论文图表”。“图片紧随此段落插入”显示当前稳定段落，也可在本节改选。多段正文必须明确选择，不能只把整章当作位置。
2. 填写图后说明、作图目标、必须逐字出现的模块／步骤／角色名与禁止内容。可选绘图方向。如果已经把 JSON 改为实际设计，可明确勾选采用当前结构蓝图；初始示例不会自动污染新图。
3. 点击“预览生成提示词（免费）”。程序在本机整理要求，不调用文字或图片模型，不需要生图 key。核对主段落、邻段背景、说明、必需文字和最终提示词；标签没有在已选材料里逐字出现时会提示核对来源。此提示是字面检查，不代表事实判断。
4. 使用独立 key 发起生图。任务保存不可变的要求快照与完整提示词。排队及发送前重新检查正文、相关参考版本、使用权限和配图边界；发生变化时在发送前阻止请求。未自动新增文字模型分析费用。
5. 生成结果保留为候选。对照实际图片逐项核对文字、节点、分支、连线方向、图后说明和目标段落，勾选确认并填写具体依据。保存候选与下载图片无需假定内容通过；插入时需要本版核对。
6. 插入由后端按绑定段落完成，图片紧随该段，图后说明紧随图片，不依赖光标。重试不会重复插入同一候选。修改图后说明或换图后，须重新核对；换到另一个原始绑定位置须重新按该位置生图。

## 提示词约束

按图类型给出独立符号和关系要求，避免用例、流程、ER 的规则混成通用作图指令。主段落限定本图范围，邻段只澄清指代，其他章节只辅助核对命名。图题和论文题目不作为新增业务证据。

提示词明确要求逐字保留标签、纯白背景、黑色细线、清楚的中文与互不重叠的连线；图中不重复 Word 管理的图号、图题和图后说明。结构、字段、模块、链上组件、结果和性能数字不得凭空补入。

修改保留既有图与约束，仅调整本次明确要求。当前必需文字清单可显式覆盖旧清单；历史正文版本仅作溯源，不与新版本并列为作图依据。每次仅发一次图片请求，不自动重试或换模型。

服务若返回改写后的提示词，会在候选核对区展示，便于比较是否偏离原约束。下载生图记录同时保留原提示词、服务改写、绘图快照和来源版本。

## 插入与检查

人工核对绑定产物、图片哈希、图后说明、目标段落和当前正文版本。后端的其他正文保存入口同样检查新候选的核对记录与位置，不能通过旧的插图入口绕过位置约束。未绑定的旧图或独立候选可显式选择位置人工核对。

生成期间正文变化时，已返回的图片和费用记录仍保留，并标为依据过期；不能通过勾选确认强行覆盖新正文。正文检查增加“图片与插入位置对齐”，发现跨章节、目标变化或位置移动会报告缺口。修改已插入图片的位置不会删除用户内容，但正式导出前须解决该检查。

实际像素中的错字、遗漏、错误连线和业务含义仍需人工核对。本次没有增加视觉模型审图，也不会把文件格式正确、提示词匹配或用户选了章节说成自动语义通过。测试使用隔离项目、模拟接口和合成 PNG；不能据此保证真实中转站的出图质量。

## 接口

- `GET /projects/{pid}/paper-visuals/positions/{sid}`：读取本节可绑定段落。
- `POST /projects/{pid}/paper-visuals/image-brief`：免费编译绘图快照和完整提示词。
- `POST /projects/{pid}/paper-visuals/image-tasks`：使用快照哈希排队；输入变化返回冲突。
- `POST /projects/{pid}/paper-visuals/{aid}/alignment-review`：记录本版人工图意与位置核对。
- `POST /sections/{sid}/paper-visuals/{aid}/insert`：固定位置、正文版本校验及幂等插入。

沿用原有独立生图配置、预算、产物和项目历史表，不需要数据库迁移。验收脚本为 `tests/test_image_briefs.py` 与 `tests/image-alignment-browser.cjs`。
