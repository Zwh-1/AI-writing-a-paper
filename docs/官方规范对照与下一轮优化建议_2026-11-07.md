## 优先级最高的四项改进

### A01：参考文献按类型格式化，并绑定标准版本

**已确认的代码行为。** `backend/app/exports.py:15` 的 `bibliography_text()` 优先照用 `citation_raw`，否则使用同一个 f-string。函数会输出年、卷、页码，但不处理期号、版本、出版地、网页地址或访问日期等字段，也没有标准版本参数。

纯函数探针输入了卷 12、期 4、页码 1—9，输出没有期号；输入网页地址与访问日期，输出也没有这两个字段。这是当前函数可复现的字段遗漏，不是模型生成质量推断。`citation_raw` 可以保留人工整理结果，但直接返回原串不能证明格式已合规。

建议拆成书目数据归一化、类型校验和格式渲染三层，首先覆盖期刊文章、图书、学位论文、会议文献、标准和网页。分别保存原始元数据、作者修订和输出文本；缺字段返回明确问题。对现有 raw 字符串保留兼容入口，增加核对状态。标准版本及学校配置进入导出快照，历史稿件继续使用其已确认版本。[S7]

验收应覆盖：不同类型的必需字段、卷期页、电子资源、责任者、省略与缺项；引用序号与去重；已有 Word 书签和正文引用链接；旧版格式选择与历史导出。真实书目核实与标点格式校验分别记录。

### A02：为长论文增加分层上下文模式，并保留全文模式

**已确认的代码行为。** `backend/app/writing_continuity.py:20` 的 `collect()` 把所有已保存章节完整加入上下文；`writing_request.py:142` 及 `writing_agent/packing.py:48` 会延后部分可选资料，但完整论文仍属必须保留内容。超出预算时停止发送，属于明确的现有产品约束。

`backend/app/source_payload.py:32` 使用 UTF-8 字节数加 512 作为输入保守估计。直接调用该纯函数，使用重复汉字构造输入并预留 8192 输出，得到：

| 汉字数量 | 输入保守估计 | 加输出预留后的额度 |
| --- | ---: | ---: |
| 10,000 | 30,513 | 38,705 |
| 30,000 | 90,513 | 98,705 |
| 40,000 | 120,513 | 128,705 |

这些数字不是服务方真实 tokenizer 或账单用量。它们说明：配置为 100,000 的接口，仅 4 万汉字就会触发当前本地预算边界，尚未加入规则、工具和证据。保守估计有其用途，后续可在已知模型上增加适配 tokenizer，并保留未知中转别名的保守回退。

建议新任务可显式选择 `full_manuscript` 与 `hierarchical_v1`，冻结模式和版本。分层模式应包含：

1. 全篇层：研究问题、章节责任、术语、关键事实与数值、论证依赖、来源版本及作者决定。
2. 当前任务层：当前章完整正文、选区边界、相关章节原文、必需规则和当前论证证据。
3. 按需阅读层：其他章节与文献的目录和稳定定位，通过现有阅读工具加载明确范围。
4. 交付检查层：按章覆盖全文检查，并执行跨章术语、数值、贡献、摘要和结论的一致性检查，记录覆盖与遗漏。

章节摘要是带版本、可重建的导航；涉及事实时仍回查原文。摘要不能取代证据或作者决定。必须区分“全篇原文已经提供”“只提供摘要”“按需读取”，不能在实际局部输入时仍声明已通读全部正文。原有全文模式及其权限检查继续有明确行为。[S1]

若把会话历史压缩也纳入该模式，需要保留 tool call/result 配对、未解决缺口、来源引用和已确认决定。当前正文上下文与会话消息历史是两类对象，不宜共用一个无差别截断器。

验收使用短论文、长论文、中英文混排、跨章数值冲突、摘要过期、权限撤回与定向修改等冻结样本。比较全文模式与分层模式的遗漏、引用支持率、作者修改量、上下文体积和实际用量，再决定默认模式；不能预先承诺节省比例。

### A03：图表规格连接最终排版尺寸和可编辑源

**已确认的代码行为。** `paper_visual_render.py:41` 的 Canvas 会按逻辑场景以至少 2 倍缩放绘制，并使短边达到 1080 像素；`result()` 写入 300 DPI。它是在高分辨率画布上绘制，并非简单放大低清截图。`paper_visuals.py:366` 的当前结构图下载分支提供 JSON 源文件和 PNG，未提供矢量输出。

`backend/app/extras.py:114` 的统计图入口将数值列转为数值、去除不可转换项后绘制直方图，保留源文件哈希、列和有效样本数。它具备真实数据来源，但图种、排版规格和数据处理记录仍可深化。

建议统一图表规格，至少记录来源哈希与范围、变量与单位、数据转换、图种、坐标与图例、图题与说明、目标宽度 mm、最小文字 pt、目标分辨率、渲染器及字体版本、输出资产版本。统计图增加缺失值与非数值排除数量、分箱参数；按问题逐步增加折线、散点、分组与不确定性展示，不能在没有实际计算时补上误差线或显著性结论。

结构图复用 `paper_visual_layout.py` 的布局场景，增加 SVG/PDF 等适合目标格式的矢量输出；统计图使用 Matplotlib 相应输出格式。Word 中的图像承载格式、兼容性与 PDF 导出需分别验证，不能仅因有 SVG 就声称 Word 全流程支持。[S9]

有效 DPI 应按“像素宽度 ÷ 实际放置宽度（英寸）”计算。例：1080 像素放到 150 mm 宽，约为 **182.88 DPI**；这只是计算示例，不代表项目现有每张图均不合格。PNG 中写入 300 DPI 元数据不能保证它按任意宽度排版后仍达到 300 DPI。最终尺寸、文字与线条应在导出页上检查。[S8]

论文规范层同时检查：图表与正文对应、图题和表题位置、编号、交叉引用、单位及必要注释。GB/T 7713.1—2025 对三线表使用的是推荐性质表述，不能在未有其他正式依据时升级为所有表格的硬性禁止条件。[S6]

验收覆盖最终版面上的文字尺寸、线宽、裁切、重叠、长标签和续表，以及来源变更后的图文过期提示。图可生成、图义正确、数据可复算、论文版面可读应分别记录。

### A04：建立可追溯的 skill 注册与按需加载

**当前边界。** 检索了 `backend/app`、`backend/migrations`、`frontend/src` 和 `prompts`，未检索到独立的 skill 注册、SKILL.md 发现或渐进加载实现。已有 `writing_agent/tools.py` 的静态工具 schema、`ai_runtime/tools.py` 的 StructuredTool 包装及专用 prompts；这些是可以复用的基础。

建议初期只做同一执行主体的技能加载，按“名称与描述 → 被选中技能的说明 → 必要辅助资源”逐层读取。[S3][S4][S5] 首批可选择文献综合、论文图表、学术表达审阅和参考文献交付，复用已有提示词及领域服务。

项目侧新增的记录可包含 `skill_id`、内容哈希、版本、触发来源、适用操作、说明和资源哈希、关联规范版本、宿主允许的工具集合、输入输出契约及验收器。`name/description` 等来自技能格式，其余为本项目拟增加的执行与追溯字段，不能冒充通用标准字段。

用户明确指定的技能优先选择；自动选择记录原因，说明实际加载了哪些内容。技能说明负责方法，确定性服务负责来源读取、统计、渲染和保存。工具授权由宿主核对，不能仅凭 SKILL.md 中的声明放宽项目、文件或代码快照范围。资源先按需读取，调用脚本仍走现有注册能力和执行策略。

验收覆盖：显式指定、自动触发及不触发、同名版本冲突、资源缺失、说明变化后的续跑、工具越界、加载额度和规范冲突。每次任务必须能回查其实际采用的技能版本。简单固定任务可以直接调用领域服务，无需每次让模型选择技能。

保留当前执行代次、请求账本与节点收据。LangGraph 的恢复会重放到相应位置，副作用要有确定的身份及复用或幂等策略。[S2] 不应把既有付费请求再放入多层自动网络重试；网络重试、格式修复和内容修订应分别计数。
