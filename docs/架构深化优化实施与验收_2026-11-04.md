# 架构深化优化实施与验收

本次对应《项目功能与架构深度评估及优化路线_2026-11-03.md》的代码实施。日期为北京时间2026年11月4日。保留既有未提交改动；没有重启生产server/worker、开启生产排空、恢复任务或发起真实收费模型测试。新后台功能在后续完整启动后加载，不能把源码完成说成现有进程已经升级。

## 一、执行一致性

### 1. 已加载构建身份、运行诊断与排空

- `runtime_identity.py`以公开源文件允许列表生成内容指纹，包含迁移SQL、API合同、前端产物、版本和能力；不读取论文、凭据和私有目录。
- server/worker分别冻结启动时身份；源码当前状态是独立观察。前端身份在构建时嵌入，避免旧页面读取新清单后冒认新版本。
- `runtime_api.py`提供认证后的运行状态、worker心跳、readiness、缓存分阶段指标及显式排空控制；health保持旧字段并增加加载身份。
- 排空不自动执行。外部新任务入队和新队列领取暂停；已经运行的同项目任务允许保存内部后继检查点，但后继继续等待领取，不丢阶段进度，也不强制打断在途HTTP。unknown保留，不用排空自动解除。
- 原生桌面使用独立受监管worker；worker watchdog与HTTP/UI进程隔离。任务观察GET增加超时、退避及断线恢复，读取失败不重放创建任务命令。本轮没有重构为SSE。

主要文件：`runtime_identity.py`、`runtime_api.py`、`main.py`、`worker_supervisor.py`、原生launcher/spec、`RuntimeDiagnostics.tsx`、任务观察仓库。

### 2. 请求身份与预算统一

- `provider_identity.effective()`分别保留requested与actual身份。完整实际配置、实际凭据摘要和三字段快照共同作为证据；历史池记录不足时保持unknown，不能拿初始账户补齐。
- 对账、费用凭证、规则收据、agent能力和相邻区间归属统一读取有效身份，原行级初始model/protocol不覆盖。
- `budget_usage.charge()/charge_tasks()`统一项目、任务、会话、知识范围与规则job占用。未归并记录按cost或预留，触及的归并组只计一次完整上界，不按请求均摊。
- 初始请求与池内真实端点预检均使用统一占用口径。重新定价仅排除当前task的pending/sent hold，其他unknown继续阻挡；paid_testing额度不会因排除自身hold而双计，也不能借此排除历史unknown。
- `execution_policy.py`提供可选阶段上限和剩余工作费用预览。上限在预留事务中检查；预测仅使用已有本地样本，不拆分账户归并账单，不自动增加预算或跳过核验。没有样本保持未知。

主要文件：新增`provider_identity.py`、`budget_usage.py`、`execution_policy.py`，及费用、计费、任务与provider模块。

### 3. 状态写回与代次隔离

`task_transitions.transition()`要求task ID、attempt及expected status，核对受影响行数。任务完成、失败、取消、通用恢复、agent恢复和整篇检查点接入条件写回。运行中进度也校验当前owner。迟到结果保存为不可变对象及审计事件，不覆盖新代次的结果。

恢复扫描在短事务内重新读取代次、状态和租约，再执行既有恢复逻辑，避免过期扫描结果变更新代次；事务不跨模型HTTP。

## 二、逻辑请求与实际尝试

新增正式迁移`022_request_execution.sql`，数据库版本由17升为18：

| 记录 | 含义 |
|---|---|
| request_intents | 一次逻辑模型请求；网络重试与DeepSeek→GPT接替仍属于同intent |
| request_intent_runs | 将现有generation_runs关联到intent，保留原失败和计费历史 |
| provider_attempts | 每次实际端点尝试的次序、身份、预留、状态、用量与结果 |
| request_execution_events | prepared、reserved、send_started、response_received、persisted及拒绝/未知事件 |

`request_execution.py`通过现有provider尝试边界和HTTP前后钩子接入。实际端点选定后，发送前重新检查来源/规则/取消/代次、该端点容量、币种、费用上限、总预算、任务/会话/阶段和规则GPT子预算。高价、小容量或异币种后备在HTTP前阻断。

失败性质与回退资格分开：明确400/422拒绝可以是known_rejected而不可重试；ReadTimeout或已有部分输出优先保留unknown/response_received，不能因为hook尚无证据而判定未发送。persisted只代表数据已保存，completed_invalid仍不代表质量通过或可采用。

已有DeepSeek最多配置次数、GPT独立有界额度、任务内保持GPT和未知不重发均保持。五次DS失败加一次GPT成功，现有六条run可以关联同一个intent，完整attempt次数可回查。

### 只读回执恢复

`request_receipts.py`提供保存执行证据的查询及能力白名单控制的远端回执查询。当前仅支持明确验证的Responses GET路径，不自动为任何服务商声明支持：

- 实际账户/端点/模型、协议和远端response ID必须匹配；能力须经本地记录verified。
- 没有能力、无远端ID、凭据已变更、回执未完成或身份不符时维持原状态/预留，不产生生成请求。
- 成功时保存原远端正文/agent envelope、统一用量与恢复证据；前后重新检查来源及当前任务输入。
- 不自动恢复任务、不自动采用，不把未知费用预留变成已验证支出。

这是一条可验证、只读的恢复路径，不承诺所有中转站都能查询，也不把X-Client-Request-Id当作远端幂等保证。

## 三、长篇质量与输入成本

### 新任务冻结协议

新写作任务增加冻结字段：

```json
{
  "prompt_layout_version": "cache_v2",
  "verification_scope_version": "claim_window_v2",
  "revision_protocol_version": "restricted_patch_v1",
  "evidence_range_schema": "evidence.range.v1",
  "dependency_projection_mode": "shadow"
}
```

历史任务字段缺失仍走原布局、全文核验和完整候选修订；恢复不读取新默认值强行升级。可通过现有缓存策略API将新任务默认回退为`legacy_full`和`full_candidate`，不会改已有任务。

### 核验投影与逐主张来源约束

`writing_quality_protocols.py`对每批主张提供目标段落及相邻窗口、明确依赖和完整已读证据范围；保存段落编号、文本哈希、提供/省略范围及逐claim允许引用来源，防止同批另一个主张的来源被误用。

未提供全文时`global_coherence=not_checked`、覆盖不完整，不能把局部支持判定标为全文通过。原全文路径保留。没有新增付费的全篇coherence模型调用，本轮不为得到“通过”额外收费。

### 受限补丁

`writing_revision_patch.py`绑定完整候选hash、段落ID、旧hash、可编辑范围、已有claim与引用库存；先验证全部操作再原子应用。禁止插入/删除/重排段落或修改未授权顶层字段；未修改段落保持不变。新候选仍经过既有结构、来源、完整性和后续核验，不把补丁协议代替事实检查。

冲突、未定位问题或无效补丁保留旧候选和原响应，不降级成无约束全文重写。

### 不可变阅读范围与影子依赖

`evidence_ranges.py`保存文件/解析/单元版本、阅读ID、字符区间及文本摘要，按当前权限和版本展开；用途限制仍由既有阅读上下文和fresh校验提供，不凭句柄授予额外用途。先双记录，不替代/删除旧阅读快照。新增审计句柄不改变旧完成响应的恢复身份。

依赖闭包目前仅shadow观测，输出受影响claim和段落，但不缩小现有版本/权限阻断、不跳过核验。开启实际细粒度跳验仍须独立金标证明，API拒绝将shadow改为enforce。

### 质量基准与性能剖析

新增`benchmark_writing_quality.py`及六个公开合成起始场景，复用原八维评分。支持已有响应的离线合同观察和显式人工评分输入；无人工记录时语义为unassessed，human_approval始终不由脚本授予。当前是可扩展的基准工具与种子，不宣称已有30个真实论文金标或真实模型质量提升。

`prompt_layout.prepare()`增加排序、块查找/复制、精确压缩和编码耗时/字节指标。它们只解释本地组装成本，不能冒充上游token命中或实际账单节省。材料LRU仍采用受限进程缓存与SQLite恢复，不引入Redis或写作跨任务响应复用。

- 任务读取瞬时失败采用有界超时/退避，401等身份错误停止；不会重发付费命令。

远端CI、实际Windows/macOS安装制品及Docker镜像构建未在本轮运行，不能称已发布或跨平台实机全验收。详细分工记录见[运行身份与发布门禁实施](运行身份与发布门禁实施_2026-11-04.md)，其中记录了一次误用逐行执行做语法检查而触发pip请求的过程异常：及时终止且安装失败；随后仅使用静态Parser检查，不再执行工作流脚本。

## 五、数据库兼容与安全生效

源码包含正式schema18迁移，并沿用迁移前备份、校验和及外键检查。迁移只会在后续初始化新代码时执行，本轮测试均使用隔离数据库，未迁移生产库。旧schema16/17知识包仍接受兼容导入。

回退代码必须理解schema18，或在维护窗口恢复已验证的兼容备份；不能直接降低user_version或删除新执行记录。原schema17程序按已有规则拒绝高版本库，这是保护，不应绕过。

排空API仅表达维护意图，不执行重启。回退新任务协议不改变运行或可恢复任务，unknown与费用占用保留。需要真实服务商能力验证或质量试验时，应另外明确预算和范围，不在启动/健康检查中收费预热。
