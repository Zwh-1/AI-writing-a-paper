# 截图文字识别例外修复

日期：2026-10-27。对应用户截图中“处理例外367项”及前三条乱码／段落残缺内容。

本文保留本轮历史结果。后续已继续逐项修复205条，当前待核验160条，详见[待核验资料第二轮逐项修复](待核验资料第二轮逐项修复.md)。

## 发现的问题

待处理列表原先只按对象来源区分“资料／规则”。课件中的课堂练习、技术讲解和教学反例都来自规则材料，因此尚未核验的OCR也统一显示在“规则”下，并重复显示恢复历史说明。用户无法区分文字尚未识别完整，还是规则用途尚未确定。

这批367条的根本原因并未消失：它们此前恢复为独立提取对象，但尚未逐条对应到完整原图。历史用途提示不能代替原文核验，局部摘录也不能替代整条候选。

本轮直接查看截图前三条对应的三个原始嵌入图，确认了两类不同问题：前两条能够按完整原图纠正；第三条的原始图片本身就缺少末句后续内容，同时存在标题和公式识别错误，不能凭上下文补全文字。

## 对前三条的实际处理

| 条目 | 原页 | 处理结果 |
|---|---:|---|
| 相关技术介绍练习 | 《实训3：文献整理与文献综述结构设计》29页 | 对照整图，纠正开头乱码及连接号，保留“选择2－3个核心技术、各写约100字”的条件，作为条件参考保留。原生页“400字”课堂练习是独立说明，没有混入每个技术的字数。 |
| 区块链核心原理 | 同文件21页 | 对照整图，纠正Nonce、PoW、PoS、MSP全称和X.509等OCR错误。结合原页“错误一：写成区块链基础课”，作为教学反例保留，不转成系统实现事实或生效要求。 |
| LMSR算法原理与数学推导 | 同文件22页 | 原图标题实际为“4.2.1”。已核对标题与首个完整段落，保存为独立摘录。原图在“该参数值影响市场价”处结束，公式与后续段落未完整核验，原候选继续待核验，明确标记“原件图片裁断”。 |

前三条的原始OCR、来源原文、原图及历史记录全部保留。前两条各使用自己的候选指纹及逐条映射，未把共同摘录写给其他候选。第三条没有因已有短摘录而被判为整条完成，也未猜测缺失句子、修正数学表达或把课件中的说法认证为研究事实。

实际待核验数量从367降为365，只有前两条完成了对应范围核验。365条继续保留待处理；没有将这批资料清零。

## 程序与界面修复

- 例外列表按“资料归类／文字识别／规则判断”分别筛选和计数，原有总数继续包含文字识别项。
- 对文字识别项显示文件和页码、具体识别问题、历史用途提示及其未核验状态；原始OCR和并列校对摘录均可展开读取，未省略原始文本。
- “查看原图与识别内容”直接进入对应来源阅读窗口，可以查看原图、完整OCR和校对范围，不再先要求在规则编辑器里决定是否采用。
- 既有用途判断只作定位提示。来源已变化时，不显示过期用途提示，也不沿用过期裁断结论冒充对新来源的核验。
- 已记录裁断的同一图像字节不能声明为完整转录。即使局部引句恰好匹配，也保持候选未完成；后续审核遗漏裁断标记仍不能绕过检查。
- 裁断状态同时传入图像识别覆盖和结构化阅读结果；读取完整摘录不代表原件内容完整。界面显示补充未裁断原件后继续核对。

当前“规则判断0”仅表示这些例外尚处于原文识别阶段，不能解释为全部规则语义均已核验。原文恢复后仍须依据具体用途和适用条件判断。
