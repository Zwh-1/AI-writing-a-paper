# 跨 API 自适应适配 - 修复报告

日期：2026-11-02，Asia/Shanghai。

## 问题

用户切换到新接口 `new5x`（`https://new.x5m5x.com`）后，系统提示"缺少绑定当前服务商、账号、模型和币种的计价依据；请在费用依据账本导入服务商报价，未发送收费请求"，无法继续计费任务。

## 根因

两个独立问题叠加：

1. **代码层**：多接口切换时没有自动适配计价依据的逻辑。`_autobind_pricing()` 未在 `activate()`/`save_endpoint()`/故障切换路径中调用，导致新接口的 `expense_pricing_basis` 始终为 `None`。
2. **数据层**：数据库里 `deepseek_pool` 的 `new5x` 端点 `input_price`/`output_price`/`expense_pricing_basis` 均为 `None`，需要手动导入真实报价或让系统自动生成保守估算依据。
3. **服务层**：之前启动的服务（PID 30088）运行于 10:16，早于代码修改时间（12:40-12:56），加载的是旧代码。

## 技术设计

**三层兜底策略**：
1. 端点已显式配置 `input_price`/`output_price` → 标记 `configured`。
2. 账本已导入该接口的 tariff → 复用单价，标记 `imported_tariff`。
3. 家族默认价（保守估算）→ 标记 `endpoint_probe`，生成 `expense_pricing_basis`，`estimate_only=True`。

**安全边界**：
- 家族默认价仅用于`_autobind_pricing`（手动切换/故障回退路径），不进入 `priced_config` 的通用逻辑，避免绕过严格计价前置校验。
- `expense_pricing_basis.kind in ('endpoint_probe', 'endpoint_configured')` 被 `source_for` 接受，但标记为 `estimate_only`，不影响已结算账单。
- `normalize_balance`/`normalize_pricing`/`normalize_usage` 对缺失/格式不一致字段提供兼容处理，从不静默置零或伪造数值。
