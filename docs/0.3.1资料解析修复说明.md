# 0.3.1 资料解析修复说明

日期：2026年10月21日。已应用到本机正式工作台。

## 缺陷与原因

旧版导入只提取PPT/PDF的原生文字，没有自动执行图片OCR，却把文件统一标成“已解析”。原资料库25份文件只有696条原生文字来源，没有图片识别来源。大量只有标题的幻灯片因此遗漏图片正文。旧版重解析还会删除页面和来源，不适合已有引用、规则或人工修改的项目。

补查发现，一份课件第20页还嵌入了DOCX，原复杂对象读取仅识别部分格式，没有读取其中的Word正文。在正式更新向量索引时，Windows报告了MSVCP140.dll访问冲突，后台进程退出而页面任务仍显示运行。

## 已修复行为

- 导入后依次提取原生文字、表格、备注和复杂对象，自动执行本地OCR。PNG等图片、母版/版式中的图片、PDF图片页和Word内嵌图片保留来源位置。PPT表格保留行列，DOCX正文与表格按原顺序处理。
- 大图分块识别，保留原始像素和几何坐标；小图适当放大。成功的OCR按图片哈希缓存，共用图片不重复识别；文字分块进入全文检索，保留PPT/PDF原页及图片出处。
- 嵌入DOCX采用只读解析，提取段落、表格和图片，来源记录包括父幻灯片、嵌入部件路径和哈希；不激活OLE。仍不支持的对象、识别失败、超时或语言包缺失明确显示缺项。
- 补解析沿用页面ID，保留全部原来源ID、人工转录和核对说明。新增内容作为候选加入，不自动确认、发布或替换论文规则包。
- 资料中心显示待补识别、缺项、识别完成与人工核对进度；提供“修复解析缺项”。资料查看器显示页级原因，并提供“补解析 / 重试缺项”和“对照整页原件”。
- Windows OCR在独立的短期子进程运行；超时或原生崩溃转为本页的可重试错误，避免将WinRT加载进ONNX工作进程。启动器会检查后台任务进程；主页面服务还在但任务进程已退出时，重新启动任务进程并恢复过期的本地任务。
- UTF-16文本优先按BOM解析。PDF单页文字提取失败可尝试本地OCR，不直接丢弃其余页面。OCR推导出的规则摘录仍保留OCR来源性质。

文本总量包括OCR候选、标记和保留的历史内容，不是去重后的论文词数，也不是识别准确率。包含图片的429页均已走完识别或未识别到文字的检查流程，结果仍需人工对照原件。低清晰度图片、否定词、数字和复杂表格尤其需要核对。

原696条来源、全部原页面ID、原页面文本、人工核对与排除状态、接口配置和密钥密文均已核验保留。16张受保护原有表摘要保持一致，规则包没有自动发布。补解析前已创建SQLite一致性备份，保存在data/parse-repair-release-20261021。

本次修复没有调用付费论文模型；本地OCR、资料检索索引与用量无关，不使用EcoAPI Key。

## 如何使用

1. 刷新现有页面，或重新打开桌面快捷方式，确认左下版本为0.3.1。
2. 资料中心查看“解析覆盖情况”。当前25份资料已完成本轮补解析，无需重新上传或重新填写Key。
3. 打开资料，对照图片或“对照整页原件”检查OCR候选。人工核对进度与自动提取完成分别显示。
4. 后续导入会自动处理本地OCR；存在缺项时点“修复解析缺项”，或打开文件点“补解析 / 重试缺项”。进行中的同一文件解析任务会合并，已经保存的来源和人工记录不会被删除。
5. 需要把新增原文整理为规则时，在论文规则页提取候选并逐条确认；候选整理和规则包发布是独立步骤。
