# 论文图表与三线表

2026-10-26 新增。入口在“写作工作台”正文下方和“研究与成果”页右上角的“论文图表”。本功能复用项目研究产物与正文版本，无需迁移数据库。

同日补齐架构、模块、类、时序、数据流、合约交互、电路及结构示意图，共支持11类设计图与原生三线表，并加入图后说明、章节关联、按章编号、Word 交叉引用与图表目录。用法与规则边界见 [论文配图规范与章节关联](论文配图规范与章节关联_2026-10-26.md)。

## 使用方法

1. 选择流程图、用例图、ER 图或三线表。初始内容是结构示例，请替换为实际项目设计。
2. 图形通过 JSON 编辑节点和关系；标题可直接填写。三线表可直接编辑多行单元格、表题、表注，增删行列，或撤销一次结构调整。
3. 点击“生成预览”检查内容与布局。修改后需要重新预览，避免保存与所见不一致的内容。
4. 点击“保存图表”，可下载 PNG、Word 或 JSON 源代码；在写作工作台还可点击“保存并插入正文”。
5. 本项目已保存的图表可再次打开修改。修改后另存一个新产物，已插入正文的历史图表不会被其他修改覆盖。
6. 每种类型的草稿分别保存在本机，切换类型、关闭窗口或刷新页面后可以继续编辑。下载的 JSON 可通过“导入 JSON 源代码”重新打开；预览支持缩放。

旧版图表打开后，预览先显示原来保存的图片。点击“生成预览”会使用修复后的布局；若输出发生变化，需要重新保存后才能下载更新后的文件。

流程图、用例图和 ER 图在本机根据结构数据排布，输出白底黑线 PNG，两边均至少 1080 像素，并写入 300 DPI 元数据。节点、字段和关系标签按文字测量后换行排布，连线避开节点，并分别选择接入位置；过于密集时给出拆图提示。流程图支持回路和自循环，ER 图支持实体自关联。三线表使用 Word 原生单元格，保留上边线、表头下边线与下边线，不含竖线和内部数据行网格；表头跨页重复，过高的数据行允许跨页。

## AI 图片与可编辑表格

在写作工作台打开时，配图依据固定为当前已保存章节。也可从“研究与成果”打开后选择章节，或直接填写实际设计要求。

- 流程图、用例图和 ER 图的 AI 图片生成、编辑固定使用 `gpt-image-2`，通过专用中转地址和独立的生图 API key 调用 Images API。配置入口在“接口与设置 → GPT 生图专用设置”，图表窗口内也可展开专用设置。详见 [GPT 生图独立接口配置](GPT生图独立接口配置.md)。
- “使用 gpt-image-2 生成（计费）”读取已保存的章节或用户要求，直接生成 PNG 图片；“使用 gpt-image-2 修改（计费）”将已有图片或代码预览作为参考图进行编辑。
- GPT 图片的生图记录只读保留，可下载、再次编辑图片或插入正文；它的像素由图片模型生成，实际尺寸在预览中显示。三线表继续使用结构化表格数据，保留原生 Word 单元格编辑和导出。
- 三线表的“根据正文生成（计费）”与“修改当前图表（计费）”使用已配置的文字模型整理表格结构。
- 连续修改未保存的 AI 候选时仍保留原始正文版本；来源正文更新后会显示核对提示。
- 候选生成后展示预览与材料缺口，保存或插入由用户明确操作。AI 结果并不自动代表功能已经实现或数据已经测得。
- 模型调用复用项目预算、用量记录和异常处理。关闭窗口后重新打开，会恢复同一任务的候选，不会因此再次调用模型。任务详情也保留在任务中心。
- 仅限本机使用的资料及其派生正文不能作为外发上下文；任务排队后、实际发送前会再次检查原始权限。

## 结构约定

代码采用 JSON 数据，不执行 Python、JavaScript、Shell 或其他任意代码。

| 类型 | 核心字段 | 当前范围 |
| --- | --- | --- |
| 流程图 | `kind: flowchart`、`nodes`、`edges` | 最多 20 节点，形状为 `process`、`decision`、`start`、`end` |
| 用例图 | `kind: use_case`、`nodes`、`edges` | 1–4 个 `actor`，1–12 个 `use_case` |
| ER 图 | `kind: er`、`entities`、`edges` | 最多 9 个实体，每实体最多 20 个字段 |
| 三线表 | `kind: three_line_table`、`headers`、`rows`、`note` | 1–10 列，1–100 行数据 |

所有类型包含 `title`。节点使用唯一英文数字 `id` 和显示文字 `label`。关系通过 `source`、`target` 指向节点，可使用 `label` 注释。用例的 `include` 由基础用例指向被包含用例，`extend` 由扩展用例指向基础用例，参与者使用 `association`。ER 字段使用 `name`、`data_type`、`key`，主外键分别标为 `PK`、`FK`；关系两端可写 `source_cardinality`、`target_cardinality`。

## 正文与导出

插入后的图片使用项目内研究产物引用；三线表保留为可编辑表格节点，表题、表注、样式随正文版本保存。现有段落生成和润写机制会保留图表结构。

整篇 DOCX 导出会对图、表分别编号，保留三线表规则、表题与表注，并按页面宽高限制图片尺寸。Markdown 保留图片引用、表格、表题与表注；独立 PDF 渲染也保留三线表边线。

## 验证

后端覆盖高清生成、无效代码、独立 Word、整篇 Word、Markdown 与交付包、项目隔离、来源权限、预算阻断及改写保留图表。浏览器覆盖三类图的预览下载、表格单元格编辑、插入保存、页面刷新、历史产物另存、候选恢复与 390 像素宽度。

AI 验收使用隔离项目和模拟模型响应，未调用用户付费接口。生成的独立三线表通过本机 Word 实际渲染检查；截图和测试输出保存在本机 `.runtime/paper-visuals-qa`，不包含在公开源码中。
