# 0.4.1 剩余功能与验收说明

日期：2026-10-23。应用版本0.4.1，数据库版本7。本版对应V4.0完成情况核查中发现的功能和验证缺口。

## 采用、版本与变化传播

旧写作入口和有据写作入口共用`adoption.commit_document`。旧入口只允许明确保留未核验状态的草稿；传入严格政策会拒绝，不能忽略政策后保存。旧草稿也会建立当前修订的句子分析和幂等回执。锁定、版本冲突、引用归属及失败回滚由同一提交路径处理。

新增的`writing_stale_reasons`分别保存来源、事实、规则、章节前提等原因。采用一个新候选只能处理其当前分析确实覆盖的原因，不能清除所有旧标记。人工处理某个原因时需指明当前正文版本和处理依据。

变化沿已保存的对象依赖和实际使用的输入清单传播。已被后续正文替代的历史会话，不再使未使用该依据的新正文过期。没有足够关联记录的旧正文仍采取保守复查。正文在会话运行中改变时，下一阶段会在发送请求前停止。

## 原文扩展、联合修改与修订

衔接检查可以按疑点请求其他章节的冻结正文版本，以完整段落为单位扩展，保存工具观察及实际发送的范围。至多扩展3轮；超预算、无法定位或仍需更多前提时保留具体未覆盖范围，不宣布通过。

在“全文与交付”可以选择多个完整候选，建立联合复核，查看所有候选的实际正文，登记明确的人工联合审阅，然后一次提交全部章节。任一基础版本或锁定冲突会使全部提交失败。局部候选需先形成完整合并稿，重新分析后才能严格采用。

修订在原有七阶段之后增加独立回归。它读取冻结的旧稿、新稿、原命题、原问题和证据，逐项记录保留、凭证据纠正、丢失、改强、修复及仍未解决的情况。缺项或未知不算回归通过。每轮结果与费用保留，自动修订仍受轮数上限约束。

## 针对真实输出的处理

模型请求中的段落、句子、来源、书目和问题使用局部短编号。程序保存短编号与真实不可变对象的映射，在验证前还原。原始正文、代码字符串、供应商必要状态和永久对象ID不被修改。这样减少模型抄写32位编号时出现的定位错误。

明确属于本次授权来源的编号即使被模型错放在书目字段，也只会作为待核验的来源关联保存；不会创建不存在的书目，不改写正文，不授予语义支持。未知或越界编号仍会拒绝。原始模型响应和字段分类记录都保留。

已完整返回但不符合JSON语法的响应最多进行一次独立记录的格式修复，费用计入同一预算。远端结果未知时不会进入这个修复路径，也不会自动重新提交。对于正文阶段的确定性本地解析失败，界面支持从已保存的完整响应重解析，不再次调用模型。

逐句标注还允许已知的空元数据字段`claims_note: null`。它不携带论断、条件、来源或通过结论，原始响应仍保留。非空备注和其他陌生字段继续拒绝；允许空字段不会绕过来源归属、执行证据层级或严格采用检查。

否定“没有证据证明测试通过”不会被程序的窄范围结构检查当成“测试通过”。复杂否定和语义歧义仍交给独立核验与人工审阅，不把这个规则声称为通用语义判断器。

## 上下文与费用

实际发送的系统提示、消息、工具和必要状态以独立输入记录保存，并按实际协议消息检查预算。完全相同的源码片段可以共享同一份原文，每个来源编号、范围、条件及原始哈希继续保留；不是将代码替换为摘要。作者核心与章节任务只引用同一输入中的完整字段，避免重复发送。

运行记录工具返回实际观察、环境、结果和原件哈希，不把整份编译文件清单重复嵌入消息。完整原件仍在本地。任何不能保留必要材料的请求都会停止，不能靠省略关键条件通过预算。

会话、诊断和对照实验预算在写入请求账本的同一事务中检查。只能确定一组调用总费用时，项目总额只计算一次；各个涉及该组的局部范围按整组上界保守计算，不虚构逐笔分摊。

## 诊断、盲评与角色政策

诊断题集在运行开始时冻结。生成只使用该变体的题目和材料；判定标准及其他变体答案留在评估侧。后来修改题集不会覆盖旧运行的原始输入或评分标准。

新增8个维度：条件与否定、证据支持、判定落实、新增主张、连贯性、修订保留、篇幅限制、核验误放/误报。每项记录分值或不适用理由、评审身份、方法及耗时。盲评包隐藏模型、配置、实验组和既有评分，随机排列回答。评审分歧保留双方原记录；裁决通过时必须明确选择所采用的完整分项评分。

支持三类可比对照：旧写作/先判定后正文、连续修改/当前状态重建、混合标注/冻结后标注。原始题目、材料、配置和采样次数保持可比，实验组交错排队，并记录全部新增阶段费用。还可交换回答左右位置检查评审的位置敏感性。

模型辅助分项检查独立标记，不写入人工评分。没有实际人工分项标注和分歧处理，不能冻结有效质量政策。资格需满足完整题集、重复次数、当前配置及冻结阈值；关键样例的必需维度不能用“不适用”绕过。登记的资格仅用于指定政策下的辅助写作，严格采用仍需当前正文的明确人工核对。

## 交付边界

严格导出会检查当前正文、全部有关核验及扩展前提的版本。未经校准的模型自称全文复核完成，也不能代替人工通读。草稿仍可导出，并附证据、映射、过期原因和未决项。

新表和不可变资源进入完整本地备份。数据库7升级前保存兼容备份，旧版本程序拒绝打开新库。含新写作对象的项目继续使用本地完整备份恢复；旧云同步明确拒绝不完整传输，这是原方案允许的阶段范围。

真实实验、失败输出和费用记录见`docs/writing-agent/completion-real-acceptance*.json`。程序测试、浏览器测试及T01—T38映射见`completion-final-tests.xml`、`completion-browser-report.json`和`completion-validation-matrix.json`。真实人工评分、正式论文通读和模型资格必须以实际记录为准；本说明不把它们预先标记为完成。
