# 0.2.3 EcoAPI接口迁移说明

日期：2026年10月21日。用户指定的新地址为https://www.ecoapi.cc。本补丁只发布接口迁移与查询诊断，保留0.2.2已有写作、知识库和验收功能。

## 配置与用量查询

运行实例及首次安装默认地址改为EcoAPI。保留已有密钥密文，不在界面回填明文。更换服务商时，用户可在“接口与设置”的API key框填写属于新服务的密钥，再保存；留空继续使用已有密钥。

余额查询依照用户提供的约定：去除地址末尾斜杠及/v1，再GET /v1/usage，使用Bearer鉴权；按remaining、quota.remaining、balance依次读取余额，按unit、quota.unit、USD依次读取单位；保留0和false。该返回值是账户额度，不代表逐次调用Token明细。

更换地址或密钥清除旧余额。更换地址、密钥或协议清除旧模型检测结果；更换模型后重新标为生成未测试。旧版本没有地址归属的能力缓存不再显示。

## 实际联调结果

以下为初次迁移时的历史结果。2026年10月21日后续排查确认：当时工作台强制直连，未使用本机已配置的 Windows 系统代理；同一密钥通过系统代理请求模型和余额均返回HTTP 200。已修复统一请求客户端的代理选择，并处理仅有NO_PROXY环境变量遮蔽系统代理的情况。模型列表、余额、普通生成和流式生成均使用修复后的客户端。

已将本机运行实例从旧服务切换到EcoAPI。密钥密文未改动，模型ID保留为gemini-4-argon，协议保留OpenAI兼容。没有发起计费生成请求。

带Bearer的/v1/usage、不带Bearer的/v1/usage，以及/v1/models均收到HTTP 403的text/html响应，页面标题为Attention Required! | Cloudflare。这是网页访问防护拦截，不是API JSON，不能据此认定密钥错误、余额为零或模型无权限。程序明确显示拦截原因，不伪造余额，不自动转用其他域名。

需要服务方确认API专用地址，或对正常/v1/usage、/v1/models调用放行。取得有效JSON后，工作台会按约定显示余额及查询时间。不得将旧服务的历史余额显示成EcoAPI的当前余额。

## 开发中的高级扩展

六项高级扩展源码已保存到项目.experimental/advanced-v0.3-20261021，未包含在便携包中，也未在当前服务中启用。该快照尚缺专属测试、界面和完整联调；模型权重下载超时，不能标记真实神经检索已验收。API迁移补丁不会开放远程协作服务。

## 回归与实机核对

144项后端测试、41项浏览器检查通过，前端类型检查和生产构建成功。实机页面验证：地址为EcoAPI、密钥仍已保存、原余额缓存为空、旧能力缓存不再显示；点击查询后明确显示Cloudflare拦截信息。后台未触发模型生成请求。

本机查询错误由工作台映射为HTTP 502，错误说明同时标明上游HTTP 403；这不表示余额为零，也不表示已经验证密钥无效。数据表记录数量及密钥密文在更新前后保持一致，数据库仍为原版本2，高级扩展迁移未运行。

实际诊断与页面截图保存在data/api-migration-2026-10-21，未放入便携包。完整回归结果为docs/v0.2.3-validation.json。
