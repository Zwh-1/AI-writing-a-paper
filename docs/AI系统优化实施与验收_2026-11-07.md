# AI 系统优化实施与验收

日期：2026-11-07。对应 [全面优化整合实施方案](AI系统全面优化整合实施方案_2026-11-07.md)。

本轮将方案中的执行、契约、证据规划、恢复、观察和对照入口接入真实代码。保留已有未提交改动，未重写用户论文、采用候选、修改模型账户、启动收费评测或重启正在运行的工作台。实际模型的论文质量与成本变化仍需要有预算的真实任务和人工原文标注验证。

## 1. 已接入的能力

| 领域 | 本轮实现 | 实际边界 |
| --- | --- | --- |
| 统一执行 | `tasks.model_call` 进入 LangChain Runnable 适配，继续使用原路由、费用预检、请求意图和实际尝试账本 | 没有增加 SDK 模型传输、重试层或云端追踪 |
| 工具与检索 | 调查工具接入实际 StructuredTool；素材搜索经 BaseRetriever 返回保留 source_ref 的 Document，再无损还原原生结果 | 范围、权限、调用ID、参数和阅读证明仍由现有领域服务校验；预览不会提升为证据 |
| 单章工作流 | 将项目理解、起草及候选核验拆为阶段服务，接入实际 LangGraph；普通章节与整篇调用共享这些服务 | 使用当前 worker 的 task 租约，不另起竞争调度器 |
| 有据写作 | 原 `writing_steps` 保存阶段结果；后继选择接入 LangGraph，保留原证据、判断与采用条件 | 继续复用已存在的阶段业务检查点 |
| 内容责任 | 从任务书、章节合同与论证卡生成 Pydantic TaskSpec，记录责任、证据需求、结论强度和源版本 | 责任点的完成依据来自已有独立核验；无结果不填造通过 |
| 证据选择 | 新任务支持按证据类型、问题相关性和来源多样性选择论证候选 | 候选相关性不视为语义支持；原文阅读和权限检查继续执行 |
| 支持关系 | 保存逐句来源支持视图、位置、摘录及核验状态；支持标签需有已核对原文摘录 | 模型核验不代替人工认可 |
| 整篇 | 整篇候选汇总章节责任及未评估范围，继续强制执行原整篇语义审查 | 章节检查不能代替全文论证审查 |
| 使用效果 | 记录排队、上下文构造、模型调用、流式首段、实际接口响应、本次执行、最终总耗时和阶段复用 | 状态心跳不计作首段正文；失败与恢复分开留痕 |
| 性能策略 | 整个任务复用受控连接池；独立语义与篇章检查支持有界并行；复用现有缓存 | 默认并发 1，可设置 2 或 3；共享事务或尝试预算时自动保持串行 |
| 对照 | 提供 A/B/C/D 任务分组、来源配对、实际提供方身份、请求数及预算占用比较 | 不发起额外模型调用，不生成虚假的人工语义评分 |
| 设置 | 运行状态页可选择新任务引擎、证据规划与检查并发，并查看阶段统计 | 改动仅作用于新任务，既有任务保持冻结版本 |

普通候选、整篇章节和补全审阅共用的素材轨迹组件，已增加内容责任覆盖及主张与原文摘录记录。图片生成继续保留独立 Images API、凭据和预算处理，并在入口清单标明其专用适配边界；不将图片请求伪装成聊天请求。

## 2. 数据与执行一致性

正式迁移 `023_ai_runtime.sql` 将数据库由 18 升为 19，沿用原迁移校验、升级前备份和新版本拒绝降级机制。启动前不直接改写当前用户数据库。

新增三类表：

- `ai_task_protocols`：按 task ID 冻结运行协议。非写作任务的原 payload 保持不变，模型探测等旧接口仍保持原参数契约。
- `ai_node_receipts`：存业务节点输入指纹、结果对象引用及执行代次，不复制原模型账单。
- `ai_runtime_events`：保存本地耗时与状态元数据，不保存提示全文、来源正文、密钥或错误原文。

节点提交前后验证当前 task owner、代次、取消、来源版本和权限。已知结果可复用；已发送而结果未知的请求继续阻止自动重发，预算预留仍由原账本管理。

同步调用写作服务也会通过条件更新取得正式队列租约，传播执行身份并在完成或异常后释放，不能借直接调用绕过新工作流的 owner 校验。已持久化的全文审查记录保留实际 generation run ID，恢复时逐一核对任务、论文哈希、阶段和完成状态。

图状态只保存不可变对象引用。检查点文件为数据目录下的 `ai-graph-checkpoints.sqlite3`，按 task、章节、图版本和执行代次隔离。新 owner 从业务收据重建有效状态，旧 worker 不能覆盖当前业务结果。

恢复指纹忽略明确的缓存命中、耗时诊断和导航 bundle 标识，保留实际原文、证据版本、实验测量字段和正文输入。用户通过现有恢复接口明确确认重新生成已拒绝的历史候选时，采用新的收据命名空间；原收据及费用记录保留，未知请求不会因此自动解除。

完整备份包含业务收据、协议元数据、引用对象和可选 SQLite 图检查点快照。恢复以业务库为权威，不能把独立图快照当作跨库原子提交证据。

## 3. 模型与依赖

新增可复现依赖输入 `deployment/requirements.ai.in` 和锁文件 `requirements-ai.lock.txt`，并将实际需要的依赖合并到主锁文件。解析时约束已有运行库版本，本轮未替换已存在的 Pydantic、FastAPI 和 httpx。

本轮解析的主要版本为 LangChain 1.4.9、langchain-core 1.7.6、LangGraph 1.2.20、SQLite checkpointer 3.1.3；完整依赖以锁文件为准。现有嵌入式 Python 3.12.14 已安装并验证这些包。

LangSmith 作为依赖存在，但所有新适配和图执行均显式关闭自动追踪，不因环境变量而上传论文或源码。收费请求继续由已配置的提供方执行。

工作台 Dockerfile、原生打包配置与完整便携包选择清单已补齐依赖、元数据、代码和锁文件。便携包使用同一份前端与后端构建身份。

## 4. 接口与使用

新增接口同时进入现有 API v2 注册与兼容映射：

| 兼容路径 | 用途 |
| --- | --- |
| `GET /api/v1/ai-runtime/policy` | 查看新任务默认策略 |
| `PUT /api/v1/ai-runtime/policy` | 更新新任务策略，不修改在途任务 |
| `GET /api/v1/ai-runtime/inventory` | 查看公开源码调用清单 |
| `GET /api/v1/ai-runtime/projects/{pid}` | 查看项目阶段统计、完成节点与预算占用 |
| `POST /api/v1/ai-runtime/projects/{pid}/compare` | 只读比较指定任务，无新增模型请求 |

项目统计支持 `task_id` 过滤并核对项目归属。比较接口需要 `task_ids`，先检查输入来源是否可配对、实际模型是否一致及有无未知请求，再由人工进行语义比较。

新任务默认使用 `langgraph_v1`、`evidence.obligations.v1` 和串行独立检查。运行状态页可以切回兼容流程或原选材策略，形成 A/B/C/D 对照；历史任务缺少新协议时继续走原解释方式。

同一任务创建的后续任务继承已冻结的运行协议；有据写作会话按首个步骤同时继承运行、输入布局与核验协议，避免中途修改全局默认值改变既有会话的后继阶段。

共享 TaskSpec 保存在服务端 manifest，模型继续复用已有 writing_brief 和 argument_plan，不发送第三份重复任务书。来源只保留版本指纹与必要对象引用，不复制 OCR 识别诊断和完整定位元数据。没有新增内容责任的有据写作阶段直接复用原章节合同，不追加空任务书。阶段预算估计与实际消息共用缓存布局及修复说明，保留真实请求发送前的容量检查。

## 5. 可重复验证

所有测试在隔离数据库中使用合成传输，不读取当前项目密钥或产生真实模型费用。代表性验证包括：

- 业务收据已提交、图检查点未完成时恢复，不重复执行节点。
- 章节完整恢复与整篇预算暂停续跑，不重复发送已保存生成请求。
- 旧 worker、来源撤回、正文版本变化、输入变化和结果哈希损坏时阻止提交或复用。
- 未知请求不自动重试；框架适配不增加网络尝试。
- 有界并行传递执行身份，并隔离 SQLite 读取连接；共享尝试额度时保持串行。
- 任务责任的分母不因模型少写内容而减少，来源标签不自动视为人工认可。
- 新旧框架在原质量策略下保持合成调用次数；探测 payload 契约保持兼容。
- 备份恢复包含新收据与图检查点，迁移可重复初始化。

在 PowerShell Core（版本高于 7.6.0）和项目根目录可运行：

```powershell
if ($PSVersionTable.PSVersion -le [version]'7.6.0' -or $PSVersionTable.PSEdition -ne 'Core') { throw 'Requires PowerShell > 7.6.0 Core' }
& '.runtime/python/python.exe' -I -X utf8 runner.py test tests/test_ai_runtime.py
& '.runtime/python/python.exe' -I -X utf8 scripts/audit_ai_runtime.py --output '.runtime/ai-runtime/inventory.json'
```

完整测试入口为 `runner.py test`。原始验证报告保存在本机 `.runtime/ai-runtime/`；源码入口审计覆盖 7 类能力，具体调用位置由脚本按当前源码重新生成，不能把静态清单直接等同于全部运行分支通过。
