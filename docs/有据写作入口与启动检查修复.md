# 有据写作入口与启动检查修复（2026-10-25）

先前的入口验证不足以证明实际项目可以开始写作。调查阶段重复发送整页 OCR 定位数据，并一次加载全部全局建议，导致实际项目超出上下文预算。页面也没有说明预算预留与后续阶段的输出额度。修复后已使用配置的主模型生成章节候选，当前正文保持不变；候选仍需核验与审阅。

## 本次修改

- 新增 `POST /writing-start`：从当前接口配置选择或建立写作配置，必要时从项目提纲建立基线，保留项目状态、正文版本、来源权限及预算检查。
- 新增 `GET /writing-preflight`：根据首个调查请求的实际消息结构计算保守输入上界、输出预留、适用规则和证据数量，检查项目与会话预算。预览通过保存点回滚，不写入项目版本、配置或任务队列。
- 写作页默认直接开始本节写作，阶段配置与预算收进高级设置。条件不足时显示具体原因和设置入口。会话默认预算使用项目可用余额，替代原先固定的 12。
- 完成的会话和候选可在刷新后恢复。HTML 设置 `Cache-Control: no-store`，重新打开时读取当前构建。
- 来源投影保留完整原文、条件、页码和原始载荷哈希，OCR 逐字坐标与重复识别记录保留在本地，不重复进入模型请求。
- 全部强制规则完整载入；建议条款按章标题与研究主题检索，未载入建议逐项记录，不视为已经核验。上下文不足时，资料以完整片段提供；其余仅作为可读取目录。目录不能支持具体主张，已用于判定或明确要求的证据不能被裁剪。
- 调查工具读取冻结项目说明和文献正文。检索结果仅作为有明确范围的预览，完整证据通过读取工具取得；工具回执会登记实际证据编号。
- 自动工作流为生成预留至多 6,144 输出 token、判定和逐句核验至多 4,096、语义与衔接核验至多 3,072，均不提高全局接口上限。每个阶段发送前独立检查实际消息规模。
- 单价未知时，默认写作配置启用同路线、同密钥、同模型的账单区间核对；仅请求数、Token 与费用边界可以精确匹配时更新费用，无法匹配的历史预留继续保留。项目预算只在用户明确授权后调整。

## 完整响应与严格校验

本地估算采用 UTF-8 字节保守上界，不冒充服务商 tokenizer 的精确计数。必要条件或明确依赖仍不能容纳时，任务会在发送前停止，不靠删减必要材料通过。

模型将书目编号与具体原文证据编号并列时，只能移除已明确列出同一本书原文证据的冗余书目编号，不增加任何证据、不修改命题与条件，也不授予语义支持。未读取来源和未知编号仍被拒绝。

逐句核验允许在适配层移除错误位置的空证据列表，并把角色说明和句子整体支持性保留为模型附注，不提升实际论断的支持程度。未对应具体原文的已知书目编号转为明确核验缺口，保留原命题、条件和书目编号；未知编号继续拒绝。已完成响应保留冻结请求、别名映射和输出原文；完全相同请求可以本地重新解析，避免为格式兼容重复付费。不能通过重解析绕过来源变化或远端结果未知。

带文献引用的候选可按完整段落投影，同时保留引用编号、码点位置和关联来源。文献导入档案路径与哈希留在本地；冲突的原始和结构化书目值都保留。资料、文件、规则编号使用可逆短编号，不重写原文中的字词。实际章节的语义检查因而无需依赖更大的接口上下文。
