# 运行身份、维护排空与发布门禁实施

本轮实现源码及隔离验收，没有重启生产服务、修改生产配置或数据库，也没有调用收费模型。当前已有任务继续使用已加载代码；源码变更不等于运行实例或既有安装包已升级。

## 已实现

- 公开源码允许列表生成内容指纹、API 契约摘要、前端产物摘要、提交及改动状态、动态数据库 schema 版本和能力清单。server/worker 启动时冻结身份；实时源码观察独立展示，不将磁盘新代码冒充已加载代码。
- HTTP health 增加已加载 build 身份，独立诊断提供数据库/worker readiness、心跳、源码不一致和排空状态。诊断 API 需要既有会话，配置修改继续校验 CSRF。
- 排空由用户主动切换，暂停接收新任务及领取队列；在途任务、未决请求和检查点保留，不执行自动重启。任务领取与入队的实际约束由共享任务模块执行。
- worker 在独立子进程发布原子心跳文件，正常退出清理；原生桌面改为拥有并关闭受监管 worker，watchdog 不再与 HTTP/UI 处于同一进程；修复冻结环境下 supervisor 的嵌入 runner 路径。
- 设置页增加实际加载身份、版本不一致、缓存策略、分阶段命中/未知统计和维护排空入口。前端身份在构建时嵌入，避免打开旧页面后读取新静态清单而冒认新版本。
- 任务观察增加 GET 超时及瞬时断线退避，只重连状态读取，不重放创建任务的命令。保留现有轮询协议；本轮未重构 SSE。
- 显式测试路径只运行指定测试；未指定路径时仍执行全量。CI 校验确定 commit 的导入、契约、测试、前端和身份；发布先验证再打标签/草稿，制品完成后公开。原生制品新增隔离启动 smoke，Docker/便携包包含来源身份。

## 过程异常

一次错误的逐行 `Invoke-Expression` 语法检查触发了系统 pip 安装请求；发现后立即终止，依赖版本不可用导致安装失败，没有成功安装证据。未调用模型、改动生产数据库或重载服务。之后改用 `Parser.ParseInput` 只解析文本，19段全部通过，不再执行 workflow 脚本。

## 构建与回退

所有修改完成后，应依次导出 API 契约、生成前端构建身份、构建前端，再生成最终身份。构建期间若源码继续改变，页面将如实显示与服务的内容指纹不同；不要通过覆盖启动身份隐藏差异。

诊断接口是增加字段与新增路由；旧客户端仍可使用原 health。缓存新任务布局保持可切回兼容版，已有任务保持冻结布局。维护排空不自动启动，也不自动撤销。回退运行代码前须核对当前数据库 schema 与旧程序兼容性，不能降级数据库或删除未决调用记录。
