# 知识库查询与来源一致性修复

核查日期：2026年10月28日，Asia/Shanghai。范围：当前项目的GraphRAG、LLM Wiki、原文证据库和写作接入。当前运行库为schema 13；本次不增加迁移、不重写原始知识或人工评审数据。

## 本次修复

| 问题 | 修复后的行为 |
| --- | --- |
| 同一知识查询重复新建数千个SQLite连接 | 同步读取阶段复用连接，操作结束即关闭；不保持长期读事务，惰性索引写入仍使用独立事务。事务内读取、回滚和提交后重新读取均有回归验证 |
| 单页Wiki直接读取缺少统一出处校验范围 | 单页也使用操作内校验与读取范围；下一次操作重新检查来源，不跨请求复用权限判断 |
| 同一问题在原始来源、结构单元通道重复计算查询向量 | 缓存本地查询向量，绑定已验证模型指纹，限128项；模型不可用或版本改变时不能复用，返回副本防止修改缓存 |
| 相同问题与原文反复执行Cross-Encoder | 只缓存模型指纹、问题、完整排序输入对应的分数，限2,048项。变化的文本重新计算，最终候选和外发权限继续重新检查，未缓存“可信结论” |
| 每条来源重复扫描已替换观察的JSON映射 | 将替换ID集合交给一次查询统一处理，继续排除旧原文；额外过滤NULL键，避免可选设置为JSON null时误排除整个语料。无需复制或删除原件 |
| 关闭语义检索后结构单元仍执行向量推理 | 结构单元通道现在遵守`semantic_enabled`设置；重排开关仍独立控制。明确关闭语义及重排时不会偷偷加载本地推理模型 |
| 同一长文在限额截断前占满阅读位置 | 先按文献平衡论断和原文候选，再应用16个阅读范围限额。重复范围只保留一次，项目证据记录分别获得位置 |
| 只有原文检索时来源文件清单不完整 | 返回的文件清单覆盖实际拟读范围，不再仅依赖图谱/Wiki引用 |
| 推理过程中来源权限或原文发生变化 | 需要交给模型使用的查询结果，在本地推理结束后使用全新校验范围，复查图谱、实体、阅读计划及原文候选。覆盖撤销外发权限、修改原文两类测试 |
| 写作上下文包含未纳入manifest的其他图谱论断 | 写作模型只收到manifest实际引用的图谱论断、关联实体及边；较大的图谱仍可在本地探索 |
| 模型回答缺少文字或类型仍可能登记为知识成果 | 登记前校验内容块类型、文字、范围和实际来源。格式错误时保留已有模型运行，不登记知识成果、不重发模型请求 |
| 保存历史错误回答可能留下空Wiki页 | 保存回答与创建Wiki候选作为一个事务，失败时回滚，不留下孤立空页 |
| 收费受阻后知识库仍允许反复提交必然失败的任务 | 状态接口返回费用阻断原因；生成回答、AI编译、辅助核对、社区报告、模型查询和模型评测提前禁用。本地检索、阅读、编辑及不生成报告的社区计算仍可用 |
| 社区按钮只有包含模型报告的入口 | 默认提供“构建本地社区索引（不调用模型）”，单独勾选后才生成收费社区报告。续建采用相同选择 |
| 全局侧栏样式把知识库标签排成高大的单列 | 知识库导航明确横向排列；手机端使用两列，不受侧栏隐藏文字和纵向布局规则影响 |

“章节准备”增加“补充原文检索”选项，默认保留原来的完整检索流程。取消勾选时，沿已有图谱与Wiki提供原文阅读范围，并明确提示独立全文/向量候选没有加入；不会把这种模式称为完整神经检索。

## 实测范围与结果

均使用现有真实资料；没有收费模型生成。测量含本机资源竞争，不能作为跨机器性能承诺或语义准确率证明。

| 探针 | 结果与限制 |
| --- | --- |
| 同一问题、同一数据、不含独立原文神经检索的进程内对照 | 修复前69.708秒，修复后1.232秒；均返回4个Wiki页面、100条图谱论断、16个阅读范围 |
| 阅读覆盖 | 同一探针的16个范围，文献数从9篇增加到13篇；没有把检索结果标为已阅读或已支持 |
| 仅全文检索的SQL定位探针 | 临时关闭诊断进程中的语义与重排设置，未持久化设置：替换ID过滤优化前10.149秒，之后3.382秒 |
| 完整图谱/Wiki、原文向量和重排，两个问题各两轮 | 最终首次分别42.107、52.020秒；重复分别8.265、8.330秒。4样本P50=25.218秒、P95=52.020秒，进程峰值RSS约1.26GB |
| 真实浏览器、不补充独立神经检索的导航 | 最后验收5.301秒，拟读16个范围、覆盖13份文献。浏览器同时验证显示费用阻断、模型按钮禁用、本地入口保留、完整阅读计划及390px布局 |

首次完整神经检索仍有明显加载和计算时间，尚未达到“所有查询均在数秒内”的目标。重复问题的向量与重排缓存不会跳过来源版本和权限检查。

## 当前知识与原始记录

实际库仍有3,770个原文观察、72个实体、3,837条图谱论断、63个Wiki页面、92个Wiki版本。这些数量不等于已核验知识数量。

确定性维护检查没有发现当前已发布页面的缺来源、过期或孤立页面问题；仍有1个尚未发布的模型候选，保留等待审阅，没有代替用户发布。该候选的来源和内容可以通过版本列表读取。

80个评测任务仍为`unlabelled`，人工盲审和论断人工核对没有被代填。与本次开始前备份比较，文件、页、来源、书目、章节、正文版本、引用、规则、事实和成果表指纹一致；外键检查为空。

费用继续遵守“缺少依据就阻止新增收费”。21笔、12.41768 USD历史待核实预留未改写，也没有增加预算或新增收费调用。

## 使用方法

通过启动器重新打开当前本机工作台，进入“文献与术语 → 图谱与Wiki”。

1. 需要快速导航时，打开“章节准备”，填写问题；可取消“补充原文检索”，先查看沿图谱和Wiki定位的原文范围。页面会显示实际查询耗时和覆盖的文献/记录数。
2. 需要完整候选召回时，保留该选项。首次可能加载本地模型；重复查询能够复用计算值，原文或权限变化仍需重新检查。
3. 在“构建与更新”选择本地原文摘录，可以预览和构建；微软组件默认只做本地社区计算。社区报告、AI语义编译等按钮在费用核实前保持禁用。
4. 原文替换、文献用途调整、排除、版本更新和外发权限变更后，继续沿真实出处重新检索、阅读和审阅，不能把缓存分数当作支持性证据。
