# 模块协同实施与文件范围

日期：2026-11-03。分析、模块依赖、数据流图与接口方案见 [模块协同通信与数据流方案](模块协同通信与数据流方案_2026-11-03.md)。本记录仅描述该方案本轮新增修改，仓库其他未提交改动继续保留。

## 已实施的通信和实际使用链

1. **统一命令入口。** `ProductRef`、`ReuseCommand`、`RelationQuery`、`ExecutionCommand` 明确来源身份、用途、目标章节和可选执行输入，并进入实际 FastAPI/OpenAPI 契约。兼容原有文件输入、v1 路径和 v2 领域路径。
2. **产物进入代码执行。** 总结、随记、统计、译文和表格等可直接选为 Python 输入。服务端重新读取真实内容并生成 `/input/products.json`；文件/资产使用安全文件名及真实原始字节。每个输入记录哈希、版本和未核验身份，代码和结果继续通过原隔离执行器。执行前后检查来源，远端执行还检查祖先外发权限。
3. **结果继续进入其他模块。** 执行结果和图片保存到原任务/资产服务，实际输入清单和来源可查看，并继续用于已有正文插入、对话或随记流程。没有创建另一套结果库。
4. **两种写作消费同一材料快照。** 普通写作、有据写作、编辑器材料面板使用 `section_materials`。快照记录整个所选集合及来源版本，采用时在提交事务内比较，防止写作期间新增、移走、取消或修改材料后静默采用旧候选。历史候选没有该可选字段时继续按原版本校验。
5. **来源与用途双向可查。** 产物卡片新增“查看流向”。服务端仅查询本项目记录的直接上下游，包括随记、资产、当前正文、执行结果和插入待办；排除旧记录版本的关系，超过上限明确提示。点击进入原功能。
6. **导出保留数据流。** 冻结快照新增当前正文依赖及执行输入/结果清单，使导出能保留实际协作链。运行凭据和额外请求字段不会进入执行输入摘要。
7. **长项目材料不遗漏。** 材料面板改为在数据库内直接筛选章节已关联记录，不再先取最近 500 份随记后过滤。

## 接口定义

| 服务或接口 | 请求契约 | 响应及调用关系 |
| --- | --- | --- |
| 产物读取 | `ProductRef = {project_id?, type, id, version, ...locator}` | 由原领域适配器读取文本、结构化文档或资产；上下文不接受客户端编造内容 |
| 原产物转换 API | `ReuseCommand = {sources: ProductRef[1..20], target, section_id?, revision_id?, title?}` | 调用既有随记、资产、草稿采用、计划、修改待办；未支持的字段或用途返回 422 |
| 原执行 API | 原 code、timeout_seconds、file_ids，加可选 `product_refs: ProductRef[0..20]`、message_id | 原 `task` → Worker → 输入准备 → 隔离引擎 → 原资产库；JSON 与文件哈希校验 |
| `POST /api/v2/projects/{project_id}/products/relations` | `{source: ProductRef, limit?: 1..200}` | `{source, selected_version_current, scope, items, truncated, limit}`；每条包含方向、关系、目标身份、状态和页面位置 |
| `section_materials.snapshot` | project_id、section_id、remote | `inputs` 和 `{record_heads, source_refs, fingerprint}`；上下文实际消费 inputs |
| `section_materials.validate` | 保存的快照、remote | 相同集合与来源继续执行，集合变化为 409，权限撤回为 403 |

新执行输入文件格式：

```json
{
  "schema_version": "paper-products.execution.v1",
  "products": [
    {
      "source_ref": {"project_id":"...","type":"note","id":"...","version":"..."},
      "classification":"unverified_reused_content",
      "title":"材料标题",
      "kind":"note",
      "text":"服务端实际读取的内容",
      "document":{"type":"doc","content":[]}
    }
  ]
}
```

文件或资产输入还包含 `filename`；原生表格附带实际 `spec`。文件总量沿用 80 MB 限制，普通文本产物合计 40000 字符。空资产不能假装成为有效输入。

验证包括对实际传输 JSON 和原始字节的断言、跨项目拒绝、远端权限拦截、执行期间来源修改、材料集合增删/移章/修改、两种写作拒绝旧候选，以及超过 500 条其他随记时仍可见已关联材料。
